# 阶段 4：已知引用原文回读验收

日期：2026-10-21。首个宿主目标及本次实际依赖为 Pi v1.3.0；Node v24.22.0。阶段 4 已完成，Recent Window 与完整 Q/X 预算仍在阶段 5。

## 交付与契约

用户批准 `PHASE_4_PROPOSAL.md` 后，先增量同步 Task §9、State §16、Recent Window §7 和两份固定 Rule，再实现生产模块。两份 Rule 模板逐字一致，生成资源保持一致。

- `memory_read` 批量读取当前 Task 的 U/A/T/R，支持 Unicode 码点 offset/limit，按顺序分配正文预算（默认 8000、上限 50000）。逐项区分引用不存在、来源缺失、原件不完整、预算不足和读取失败。
- 可选 items[].task_id 只读取已知来源 Task 的 U/A/T，返回当前 Task 的稳定 R；不搜索、不切换 Task、不改认知版本。Task 切换与回读同轮时拒绝冲突。
- `memweave.aliases.v1` 与 `memweave.originals.v1` 只保存定位。Task 锁保护别名序列，fork 复制去重；原有 references.v1 和 State 事件格式不变。
- Session 原始条目与模型展示投影分开。回读不使用 context_edit 后的文字，也不从截断视图拼回；正文只提取 text，保留工具名/原生调用 ID 来源信息，不把 arguments、thinking/signature 拼成普通正文。
- 原生 Bash 的 fullOutputPath 在下一次推理前转存到既定 blobs。按 SHA-256 寻址、流式复制与有界范围保留，读时核验哈希/字节长度；文件为 0600，新目录为 0700。不复制小消息或已有 Session 图片。
- 图片先返回附件 R，明确读取且模型支持时返回完整原生 image 块；字符切片被拒绝，单次合计不超过 10 MiB。当前实现检查 base64 和基本容器特征，不包含完整图像解码器；实际 Session 保存前的缩放/省略无法逆转。
- R evidence 回到最终原文/附件校验；仅新认知提交需要重新校验。已提交的同一原生调用重试先识别原提交，再返回确认，来源后来丢失不能把它误判成未提交。为此 StateStore 的内部证据集合允许延迟获取，持久化协议和原有幂等标识不变。

主要修改：`src/memory/{model,text,metadata,service}.ts`、`src/pi/{original-source,original-image,session-memory}.ts`、`src/storage/{paths,blobs}.ts`，以及 Task/State 与扩展注册的必要接线。生产入口现有 10 个工具；不增加运行依赖、独立宿主或第二份历史存储。

### 本阶段边界用例

- Unicode emoji/组合字符、跨流块 CRLF、空尾部和越界偏移；不截断半个字符，不去空格或做 NFC。默认 8000 与上限 50000 使用真实 Pi 工具返回验证，后续条目明确 budget_exhausted。
- U/A/T 来源与原生 tool call 配对；context_edit 不覆盖原件。原始消息字节/对象保持，State 与 Rule 仍只在请求中呈现。
- 同一批的坏引用、来源 Task 不存在与其他成功条目分别返回。仅有截断片段时 total_chars 不冒充全文长度，source_complete/range_complete 均不假报完整，并说明全文字符位置未知。
- R 去重、磁盘重开、fork 与两个 Pi Session 实例并行分配同一来源只产生一个别名。跨进程目录锁另有既有独立 Node 进程测试；本轮 R 并发用例本身是同进程中的两个 Pi 实例。
- 真实执行原生 Bash 产生 2500 行输出；模型续跑前已保存原件。删除 Pi 临时输出并重开后仍能读取第一行起的全文范围；blob 损坏明确报错，其他用户引用仍可读。
- 原件写入目录真实不可用时，下一次推理没有发生；修复后重新准备能保存同一来源。别名元数据追加故障使用故障注入验证，不发布可用别名；新建磁盘 Session 运行时可重试。
- 来源删除后 R 回读失败，新的 R evidence 写入被拒绝；此前已提交的同一原生调用重试仍确认原版本，不再提交或回滚。
- 程序生成有效 PNG，通过 Pi Session/工具结果验证附件别名、模型能力拒绝、范围拒绝和原生图片块；损坏编码、不支持容器和字节限额有单测。没有向真实视觉模型发送图片。

## 已观察并修复的问题

初始缺少模块的测试先失败，再实现。图片最初使用的静态 PNG 夹具被 Pi 自身省略，改成程序生成有效 PNG 后验证原生图片链路；另明确设置测试模型的 text/image 能力，避免把 Faux 默认能力误当成文字模型。截断片段的 range_complete 曾误用可得片段长度，已修正为不承诺全文范围。R evidence 的提交确认曾先检查后来失效的来源，新增失败测试后改成仅在新事务校验证据。

这些修复不引入新的 State 事件、原文映射格式或核心记忆语义。完整检查通过后形成阶段提交；不以测试替身或图片块持久化代替真实供应商验证。

## 保留边界与清理

- 当前只验证 Pi v1.3.0。第三方重写 Bash/工具结果、虚拟模型路由、动态声明等组合仍不宣称兼容；自动压缩、原生恢复记录和共享配置的已接受边界不变。
- 读取的是 Session 已保存的历史正文/图片及已保留的完整输出。没有保留、已被工具省略或无法解释的历史表示不能凭空恢复；不会读取业务文件当前内容冒充历史原件。普通 Session/原件被删除时按来源缺失处理。
- 图片基本容器检查不能证明完整像素解码或视觉理解成功；其他不支持的二进制不作为文字原文返回。真实 DeepSeek 用例只验证文字。
- 完整回读标记已在原生工具 details 中保留实际返回范围；阶段 5 再将其接入 X 预算、紧接请求豁免及网络重试。当前未开启 Recent Window 裁剪，不能宣称完整半额 token 预算已验收。
- R/原件定位的少量 custom 元数据和必要 blobs 属于运行时数据，禁用/卸载不删除。崩溃可能留下孤立 blob，本阶段不自动清理。完整原始交互仍只在 Pi Session。
- 本机 DeepSeek 私有 auth 在仓库外，测试后逐字核对未改动；没有把凭据写入代码、报告或测试夹具。临时 Session、包、缓存、测试原件与 Pi 输出文件均在系统临时目录，成功/失败均清理。
