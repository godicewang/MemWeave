## 一、目的、范围与影响

Agent 总预算从模型容量的 1/2 改为 3/5。State 默认逻辑容量 500、每批管理最早 100 个候选，正文上限 100 字符、保留上限 20 和比例约束不变。模型决定保留什么，程序不自动删认知、不裁剪 State；提醒期间仍允许临时超条数，但不允许新增内容将 State 推过其 token 准入预算。

用户明确确认 State 比例 12.5%、系统与工具 15%、Recent Window 37.5%；其他比例沿用已同意方案。State 同时受条数和 token 管理线约束，小模型可能更早收到管理提醒。State 整理仍影响同一 Task 的所有会话；原始 State 事件和 Pi Session 保留。

比例用于规划。安全与输出预留不借出，其余实际未用额度给普通 Window；系统、最新用户、完整回读、原生协议成本超过规划值时也可占用普通 Window。State 写入有独立准入限制，已有大 State 可先挤普通 Window进行整理；完整必要内容放不下时明确取消，不能借用模型剩余 40%、静默截断或生成摘要。

config.json 中省略 recent_turns/evict_turns 时按实际模型计算；旧文件显式数值及 Session/分支覆盖优先。不因升级覆盖旧配置。运行时 rule.md 不自动覆盖。预算快照与 State 放入同一末尾临时消息；Recent Window 提醒在它之前，不写 Session、不占事件或消息计数。

不新增工具、State 事件、Pi custom 持久化类型、聊天副本或独立 Agent。既有持久化格式不变。本轮不混入全历史来源核验缓存优化。

## 二、技术契约与实现

### 容量与比例

`C = floor(C_model * 3 / 5)`，使用安全整数计算，包含输入与单次输出。比例固定在实现中，不增加用户可随意修改的比例字段：

| 分区 | 占 C 比例 | 核算 |
|---|---:|---|
| State | 12.5% | 完整 Goal、活动 F/D 正文、ID、证据 ID 和格式；证据解释只在回读时计入 X |
| 普通 Recent Window | 37.5% | 基础规划，接收其他分区未用额度，实际使用唯一 Q |
| 输出 | 10% | 默认取比例与提供方/宿主声明输出上限的较小值；用户显式输出设置按实际预留并校验 |
| 系统/Rule/AGENTS/工具声明 | 15% | 实际有效内容，不另复制工具 schema |
| 最新真实用户 U | 5% | 完整保留；历史用户为普通正文 |
| 完整回读 X | 10% | 已授权的 10 条消息生命周期内结果与图片，无重复计费 |
| 原生历史协议 P | 5% | 工具名/调用 ID/参数、需回传的推理/签名、消息包装及临时提醒/预算快照；不计本地 usage、timestamp、details 等未发送元数据 |
| 安全余量 A | 5% | 不借出 |

逐项向下取整，余数归普通 Window。`Q = floor((C - R - S - O - P - A - U - X) / M)`。M 仍为全部选中真实消息数，包含 U/X；不增加剩余额度二次分配。普通正文按单条同一 Q 裁剪，引用头、截断标记共享 Q，参数/推理/签名不裁剪。M=0 不除零。

### 配置与自动窗口

全局文件仍只有六个已知字段；四个 State 字段必填，默认 `500/100/100/20`。N/B 可省略：先合并分支显式覆盖，再对缺失值求默认。N 缺失时，`N = clamp(20,200,10*floor(floor(0.375*C)/(2*256*10)))`；B 缺失时 `B = max(1,ceil(N/5))`。已提供的字段不静默修复，B>N 报错。纯自动时三个示例为 50/10、110/22、200/40（模型容量 131072、262144、1048576）。模型变化只改变自动值；实际 N/B 变化沿用既有 reset/原文重选，不新增持久化字段。

Rule 继续只支持六个配置占位符，使用本次解析后的有效值。预算快照由程序直接渲染在尾部，不新增表达式或模板占位符。只有已核验容量才能解析缺省 N，不能用展示名猜容量。

### 计数与分发

DeepSeek 官方 Flash V4.1 使用固定来源与校验和的官方 tokenizer 数据，通过轻量纯 JS Tokenizers.js 计算文字 token。只计普通文字与实际会发送的协议内容，不对整行 Session JSON 计费。提供方包装采用明确的保守余量，并与实际 API usage（包含缓存 token）对照，不宣称本地分区和供应商内部模板完全逐 token 相等。没有匹配分词器的组合保留明确标记的保守估算，不冒充精确计数或宣称已验收。

分词器资源和上游许可随同一 Pi Package 发布；固定版本的 JS 运行依赖不捆绑 Pi SDK，不要求用户安装 Python/Rust 或执行独立安装器。计数结果缓存限于本地有界数据，不新建运行时数据文件。

### 请求快照、输出与尾部

一个 context_with_system 捕获经核验容量、配置、分词器、输出及 Task/State；先渲染最终 Rule，再选 Window、分配 Q 和生成末尾 State/预算。预算快照包含 C、各分区规划/实际值、State 条数/正文上限/管理线、N/B、E/M、Q、输出上限与估算方式。它不是真实用户发言或新证据。

预算快照自身计入 P，先预留有界长度，生成后复核；不得在预算完成后无计费地补入。原生 Request/Session 不持久化预算正文，不新增每轮时间戳。提供方内部重试复用同一快照。

使用 Pi v1.3.0 公开 before_provider_request，仅将对应输出字段约束到同一快照 O，并校验目标模型/字段；不重新组装历史、不包装 prepareRequest、不改 Pi 核心。不支持的 payload/路由组合先 abort 再报告；预算与实际输出参数必须一致。

### State 管理与提交准入

活动 F/D 达到 state_max_events，或完整 State token 达到 `floor(0.8 * State规划预算)`，任一条件满足即准备既有批次。候选仍是最早 min(state_evict_batch,活动数) 项，最多保留 min(活动数/10,配置上限,候选数)。token 触发不改变 StateBatch 或 slide_window 格式；重启仍从原始记录与现有批次定位恢复。

initialize/state_append/update_goal/modify_fact 在 Task 写锁内，对实际拟提交 State 重放并检查 token；超 State 准入预算的增长整批拒绝，不写 State，说明先整理、缩短新增或换模型。已有超配额 State 的非增长修正和 state_remain 仍可进行；幂等重试先识别已提交操作，不能因之后预算变化误报未成功。正常次数超限仍可在 token 预算允许时追加。外部固定内容巨大或已有 State 切换到过小模型仍可能导致请求不能发送，明确报告而不篡改认知。
