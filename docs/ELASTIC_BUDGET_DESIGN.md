# 弹性上下文分池（2026-10-25 用户确认）

## 一、目的、范围与取舍

保留模型容量的 60% 作为基础规划，再开放模型容量的 20%。先保障实际必需成本，将剩余额度一次分池：40% 专供回读、40% 专供普通 Recent Window、20% 留作安全余量。回读未用额度不借给 Window；不为填满上下文而补齐短消息。模型外层至少 20%、基础安全预留和输出预留继续保留，不能把相同闲置额度重复算作多层余量。实际空闲比例取决于输入和输出设置，不能保证任何负荷下都有 30–40%，也不据此保证模型质量。

用户确认回读不借 Window：池收缩时，尚在期限内的回读也可被截断，末尾附 `[TRUNCATED]`。固定 Rule 在回读说明处始终提醒可用 offset 续读；不在发生截断时临时插入另一条提示。到期回读进入普通 Window 的受限子集，避免长期占据近期正文预算。

不改变 Task/State 工具参数、引用、Session 原文、事件计数、N/B、State 准入或持久化格式。不增加 Agent、摘要、工具或运行时文件。所有变化限于请求视图、回读返回限额与可选策略配置。未启用模式沿用原生 Pi。

## 二、计算与实现契约

### 同一请求快照

设经核验模型容量为 C，基础预算 B=floor(C*model_percent/100)，默认 60%；额外开放 E=floor(C*extra_model_percent/100)，默认 20%、允许降低，最多 20%。上限 L=B+E，不超过 80% 模型容量。基础八项规划保留，State 准入、自动 N/B、默认输出 O、基础安全 A 继续从 B 计算；旧配置继承新策略，不迁移旧 scope。

K=实际系统/Rule/工具声明 R + 完整 State S + 最新真实用户 U + 必要协议及临时快照 P + 实际输出预留 O + 基础安全 A。所有历史消息的不可裁剪协议在 P 中计一次；回读正文/图片不再提前从 K 扣除。K>B 时先使用 E；K>L 取消请求，不截断 State 或最新用户。

F=L-K；读池 Xmax=floor(F*40%)；普通正文池 Wmax=floor(F*40%)；池内安全为 F-Xmax-Wmax（默认约 20%，含取整余数）。各池分别按实际需求使用。三者之和必须等于 F。回读额度不借出，Window 未用额度不反向扩大读池，任何安全预留不借出。

例如 C=1000k、K=190k，则 F=610k；读池/Window 各 244k，池内安全 122k，模型外层 200k。若基础 A=30k，三层安全合计 352k；输出已在 K 中，不能再把基础各规划的闲置逐项叠加一次。

### Window 一次按需分配

不执行基础 Q 截断后再补额度。先保障每条消息的引用头和必要截断标记，随后按实际需求一次分配；只截断普通文字，所有原生调用 ID、参数、reasoning/signature、配对和消息顺序保持不变。

默认权重：当前最新工具轮事件 50%，其之前最近 3 个完整交互事件 35%，其余选中事件 15%。当前结尾不是工具轮时第一组为空；最近组取结尾最近 3 个事件。最新用户不参与普通正文分配。组间权重是软分配：空组和已满足组的剩余额度只在仍有需求的普通组之间按权重转移；组内按事件、事件内按消息公平分配，短正文不补齐。分配和最终 Unicode/BPE 截断均有整数上界。

经真实调用、返回正文和既有机器标记核验的到期回读，独立受 Wmax 的 10% 合计上限约束，不因仍在最近工具事件内绕过。其实际未用额度留给其他普通组；不从读池额外取钱。必要头/tag 都算入其限额，连最小引用/tag 都放不下时取消请求。

### 回读工具与生命周期

memory_read 和历史 state_read 的字符/项数/图片硬限额继续生效。首次返回额外检查当前读池可用额度，计入完整 JSON 返回包装、正文、证据、图片与保守原生包装余量。按请求顺序缩短可读正文/证据，保留合法结构、引用键和真实完整性字段；图片只整体保留或整体省略，省略后仍可按 R 重读。若连必要返回元数据都放不下，返回 READ_BUDGET_EXCEEDED 工具错误，说明额度，不能伪造原文。

截断结果另以文字块附固定 `[TRUNCATED]`，不把该 tag 伪装成原文正文。机器范围标记只描述实际返回项，不能继续宣称完整。没有 token 超额时字符范围语义不变。历史 F/D 没有 offset 参数，需减少 event_ids 或字符预算；Rule 不虚构其 offset 能力。

已选活跃回读与新回读共享同一读池；不能让旧内容占满后阻止 offset 续读。工具执行时依据该原生 assistant 已声明的全部回读调用，为既有结果与新调用按需求公平预留份额；新调用实际未用份额可在同批后续回读之间回收。旧回读在后续请求中允许缩短展示，不动原始记录。并行工具在返回前同步核算并预留；同一原生 assistant entry/tool call 重试不重复扣费。下一逻辑请求从唯一 Session 原文重建，不新增持久化账本。模型/Session 改变不得沿用另一帧的池。

回读期限仍为结果之后不足 read.lifetime_messages（默认 10）条真实消息，按 user/assistant/每条工具结果计数。核验过的部分回读也受池约束，不因已截断而逃到不受限制的普通组。活跃结果合计超读池时在请求视图分配可容纳前缀并附 tag，不挤占 Window、不取消整个请求；图片不足时恢复原件引用。不修改已持久化结果，不把展示截断误认为原件丢失。到期后进入上述 10% 子集；重读只开启新结果自己的期限。重启/fork/tree 按当前原生祖先链重建年龄。

### 配置、固定 Rule 和验收

新增全局部分覆盖组 elastic_budget：extra_model_percent=20，pool_percent={read:40,window:40,safety:20}，window_weights={current:50,recent:35,older:15}，recent_events=3，expired_read_percent=10。比例最多两位小数，各分组和为 100%；extra_model_percent 为 0–20，其余百分比为正且最多 100%，recent_events 为正安全整数。保留旧六字段分支契约，不新增通用设置工具。

agent_context_percent 仍表示基础百分比。固定 Rule 改成“基础规划＋实际总上限以末尾快照为准”，不硬写可配置分池比例；快照明确显示 B/E/L/K/F、读池及普通池的上限/实际、池内/外层安全、输出和到期回读限额。模型不能通过提示词借出池或改设置。同版本自定义 Rule 的原有保留规则不变，分发默认模板三份逐字一致。
