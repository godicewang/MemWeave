# 首次本地索引优化验收

2026-10-26。本记录只覆盖已独立完成的索引垂直切片及疑难case记录。澄清工具、移除initialize及其替代绑定检查范围已经用户确认，由后续切片实现；本记录不声称这部分已经实现。没有发布npm，没有改动本机日常安装。

## 改动与不变边界

用户要求在不影响效果的前提下改善首次本地索引体验。先同步Task规范§12，再增加边界测试，最后修改：

- `src/task/search.ts`：每块最多16个Task，变化文档合并一次worker通信；worker仍逐文本推理，模型文件、前缀、512-token处理、mean pooling和归一化未改。每次最多4个独立派生写入，每项保留原锁与原子替换；整组等待结束后再报告失败，取消后不留下未等待的后台写入。
- `src/task/service.ts`、`src/extension/register.ts`：通过原生工具partial update传递“已完成/总数、已更新项数”；最终返回仍是原Top-k数组。进度不写Session、不传入模型，不增加模型请求。
- `tests/integration/task-search-batch.test.ts`：批次上限、完整排名等价、单项失效、取消、坏批次、写入失败、权威源损坏，以及原生进度不入历史/上下文。
- `tests/live/task-embedding-batch.test.ts`：真实本地E5逐条与通信批次逐位比较，覆盖超长文档截断和超长query拒绝；零远程API。

未变化Task继续复用文档向量。缓存格式、State/Session、恢复定位、排名权重与Top-k语义不变；不引入向量数据库，不宣称整个Pi进程内存下降。

## 前后对照：同一组1000个Task

系统临时目录中建立1000份真实格式的合成Goal State。优化前源码为`10b4ef8`；前后使用同一批权威文件，每次使用全新的派生缓存目录。各执行3次冷建索引，每次后接3个热查询，使用真实本地E5 Q8；模型资源已下载并校验，时间不包含首次下载。Node24.22.0，Pi1.4.0，未调用远程模型。

冷索引中位数减少约**39.18%**；热路径保持同一量级，不能据此承诺任何设备或任务数都固定加速39%。初次下载及其他并发工作会影响实际耗时。

**等价性：** 前后6次运行，1000项文档向量及截断标记的合并SHA-256全部为`0279b09516cf99ee48c915d1abd81c11ecd0914b955bea6dbaa2f663570287b2`。支付英文、退款中文、登录中文及重复查询的Top-k完整结果（Task ID、顺序、融合分数、各通道名次）前后逐项相同。另用16条中英文/emoji文本，包含超过512 token的长文档，真实本机逐条推理与通信批次的向量和截断标记也逐位相同；超长query仍明确拒绝。

**内存：** 前后三次峰值RSS分别约811/884/919 MB与782/853/921 MB。整体仍约0.9GB，没有证明总进程内存显著降低，也没有据此认定泄漏。16项通信分块不等于16项张量同时推理；现有派生缓存上限和单worker生命周期未改。

完整原值、Top-k及哈希见[脱敏对照数据](evaluations/2026-10-26-index-batching.json)。临时脚本、合成State、模型链接、派生索引和临时npm缓存验收后删除，保留既有公共模型资源及仓库外私有认证。
