# 最新真实用户请求与请求内计数复用

## 第一部分：目的、范围和取舍

2026-10-25 用户授权修复取消恢复后旧用户要求抢占最新要求的问题，并优化大正文的请求准备时间。积压恢复/新 Task 冷启动及阶段记忆闭环本轮只提出方案；回读池隔离明确保持设计。

优先级修复只在当前原生分支的最新真实用户消息实际进入 Window 时，给请求视图的该消息头增加 CURRENT_USER_MESSAGE 及简短说明：冲突的较早用户要求由本条取代，其余兼容要求继续有效。固定 Rule 同步说明；不把末尾 State/预算、工具正文或引文当作最新用户。完整用户历史仍保存，不改变事件计数、工具配对、Window 范围或批次提交。该头是程序提示，不是新证据引用，也不提高用户相对系统规则的权限。

已有同版本自定义运行时 Rule 不手动覆盖。请求头本身给出简短优先级说明，使既有正常模板也能识别；新默认 Rule 则明确固定协议。模型仍可能误解复杂要求，因此须通过实际 DeepSeek 取消/恢复及正常续跑测试验收，不宣称自然语言约束绝对保证。

性能改动只复用同一次 Window 请求准备中完全相同文本的计数结果，避免再次分词。保持匹配 tokenizer、prefix 候选验证、最终成本检查、所有分池和截断输出不变；不增加长期正文/token ID 缓存、不缓存元数据 GET、不跳过来源核验。

已知 UTF-8 字节计数器保持直通，避免缓存哈希比原计数更慢；需要分词的计数路径才使用复用。计数缓存最多 4096 项、估算 32 MiB；超限 LRU 淘汰，单项过大不缓存。它只在一个 prepare 调用中存在，成功/错误/取消均清除；后续回读工具保留原始 counter，不持有该缓存。该记账上限不代表整个 Pi RSS 上限；不同文本、首次编码和 Pi 自身复制的成本仍存在。

## 第二部分：实现与验收

- 最新用户定位依据当前分支原始 Session user entry，不能根据 API 列表最后一个 user 角色或正文自称确定。只有该 entry 已按既有范围选入时标记，自动工具续跑沿用同一真实用户；被窗口移出的用户不额外常驻、不伪造 U 编号。无 Task 也可标记，已有短引用保持原义。
- 提示头参与最新用户成本和最终预算；只修改渲染副本，不写 Session/custom 元数据或 State。固定 Rule 两份规范及 resources/rule.md 同步逐字比对。
- request-counter 只按完整字符串等值复用；失败不缓存，结果与原 counter 一致，prefix 继续委托原实现。内存/项数记账和淘汰集中实现。finally 清理，不跨工具续跑、网络重试准备或模型切换复用。
- 先补正常/失败/取消/工具续跑/分支/未绑定 Task 的定位和原文不变测试；缓存测试覆盖等值命中、模型/请求隔离、上限/淘汰、过大项和异常。官方 tokenizer 对照检查配额、截断正文和最终预算逐字相等。
- 在相同输入、相同 tokenizer 和相同展示输出下做交替顺序性能测量，区分本地性能与真实 API。真实 DeepSeek 使用仓库外私有配置；临时驱动和 Session 清理，不发布。

### 同输出的性能对照

401 条消息，普通正文合计 1525068 UTF-8 bytes，Unicode/短引用及固定事件组；两轮预热后各 5 次，前后顺序交替。两侧使用同一 allocate、预算、tokenizer；差异仅为请求内计数复用。每轮计算完整返回的 SHA-256，配额、截断正文、成本和池限制完全相同。

| 计量方式 | 无复用中位数 | 本轮中位数 | 说明 |
|---|---:|---:|---|
| 官方 DeepSeek V4.1 tokenizer | 925.07 ms | 727.71 ms | 约减少 21.3%；底层 count 调用 2707 → 1179，prefix 调用仍为 376 |
| UTF-8 字节保守计数 | 27.53 ms | 27.80 ms | 保持直通；不宣称提速，样例差异不足 1 ms |

官方样例缓存 1179 项、估算 4571968 bytes，dispose 后为 0。单测另外覆盖项数/字节淘汰、超大项不缓存、异常不缓存、释放后不再积累、请求/不同 counter 隔离。初步对照发现给廉价字节计数也加缓存反而变慢，已改为直通；最终表是修改后的结果。

本地性能不是供应商推理或整次请求提速比例；模型元数据请求、首次分词、不同文本、prefix 候选编码及 Pi 自身历史复制仍有成本。没有用粗略计数替代官方 tokenizer，也没有引入跨请求正文或 token ID 缓存。
