# 阶段 3：完整 Symbolic State 验收

日期：2026-10-21；Pi v1.3.0，Node v24.22.0。

## 已确认并实现的行为

先按用户要求写出易读说明和技术细节，再经确认同步 State §15、两份固定 Rule 模板及架构。用户修正的满窗行为已采用：提醒的同时正常载入新增认知，允许暂时超过 2000，不引入排队。固定模板逐字比对通过，发布 Rule 资源同步生成。

五个 State 工具已接通正式入口：state_append、update_goal、modify_fact、state_read、state_remain。Goal 更新同步索引摘要/关键词和可选项目名；modify_fact 原子归档旧 F/D 并生成新 F，完整历史继续编号；state_read 返回指定 Task 当前认知，不切换 Task。已归档或退出窗口的 F/D 仍可作为历史证据。

窗口只计活动 F/D，当前 Goal 常驻；默认 2000 触发、最早 200 个候选、最多保留 20，同时受 1/10 比例限制。保留项维持原序，不变成永久钉住；后续可再次成为候选。新认知可使活动数临时超限，提交滑动才移除未保留候选。若仍达到容量，下一请求提示新批次。

State 原始 JSONL 前缀保持，modify_fact 和 committed slide_window 沿用既定结构；state.md 由重放生成，提醒正文不写入 State 或 Session。Pi custom `memweave.state.request.v1` 只保存本次批次的定位与限额。工具按来源 assistant 找到其请求定位；批次已提交则幂等返回，选择冲突或候选被改变则明确拒绝，不重复推进。

## 实际执行的检查

```sh
npm run check
npm run test:live
npm run test:distribution
```

- 资源一致性、严格类型检查、**80 项常规测试通过**，常规组没有调用外部模型。
- 最终独立真实 DeepSeek 整组 **5 项通过，共 18 次推理**：原有三项 2/2/3 次；Goal/读取 5 次；State 满窗/滑动/修正/读取 6 次。后两项为本阶段新增，默认 2000/200/20 由程序测试覆盖，真实窗口测试采用隔离的 10/2 配置。
- 开发中先执行边界测试再实现；曾因测试把用户原文中的同名短语当成注入提醒、以及要求模型固定回复口令而失败。均已改为检查原生消息角色、持久化结果和成功工具调用后重新运行；这些测试失败不算通过，失败夹具已清理。
- DeepSeek 认证仅来自仓库外私有配置，测试前后逐字一致。API key 不写入源码、夹具、日志或发布包。

| 范围 | 实际验证 |
|---|---|
| 默认窗口 | 1999 个 F/D 不触发；第 2000 个触发 200 候选；拒绝保留 21 个，允许 20 个；新增 5 条立即可见，旧批次 ID 不变 |
| 计数与 ID | Goal/滑动等操作改变版本而不占 F/D 数；归档 Fact/Decision 后两类 ID 均不复用；小窗口比例限额可为 0 |
| 归档与证据 | 活动和已移出但未归档 ID 可被原子修正；重复、未知、已归档 ID 不合法；历史 evidence 保留 |
| 提醒 | 按 F/D 上界给出范围，不枚举整批 ID；State 注入只有一份，提醒仅在请求尾部；state.md 不含提醒 |
| 并行与冲突 | Pi 默认 parallel 工具下 append/remain 两种排列均成功；两个实例已看到同批后只提交一次，保留选择冲突明确报错 |
| 旧批次 | 归档候选使批次过期；无提醒的新请求不能偷用旧祖先记录；配置变化不能扩大旧请求限额 |
| 写入与重试 | 实际只读目录导致 State 提交失败，原日志、批次和提醒保持；修复后同调用只提交一次；派生写入失败后磁盘重开可重试，不再滑动 |
| 请求取消 | 批次定位故障注入时推理新增数为 0；未写 slide_window，不伪称移动 |
| Goal 索引恢复 | 提交后索引失败可修复；实际 reload 后从原生调用参数恢复；旧调用重试不覆盖新 Goal，原 task_create 重试也不倒退认知 |
| 原生加载器 | 实际加载并执行正式 Task/State 模块，包括 update_goal、modify_fact、state_read、state_remain；本地/npm 归档/已提交 Git 入口回归 |
| 原生结构 | 既有 tool IDs/arguments/result 配对、签名和多模态结构回归保持；原始消息不被窗口改写 |

state_read 的完整 State 作为用户主动调用的正常工具结果会被 Pi 保存；这不等于自动 State 注入持久化。验证按原生角色和来源区分，不能仅凭 Session 中出现 `# Symbolic State` 就判定泄漏。

## 未验证与后续边界

完整 memory_read 和 R 别名仍属阶段 4；Recent Window、完整 token 计量/输出预留/Q 预算与裁剪仍属阶段 5。当前半额容量已派生，但不将阶段 3 视为完整请求预算验收；临时超量 State 不因此获得未来突破总预算的例外。

State 日志仍每批原子替换，未做长期压力或断电测试。其他 Pi 版本、任意第三方扩展和 codemode 嵌套写工具没有新增兼容声明。卸载后的共享压缩设置等既有副作用不变。分发组验证本地 npm 归档和 GitHub SSH 固定 ref，不代表 npm registry 发布或 HTTPS 已通过。

所有模型 Session、故障夹具、临时入口、包和工具缓存均位于系统临时目录，成功/失败后清理；用户真实 Session、业务仓库和私有认证未修改。
