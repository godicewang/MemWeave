# 新 Task 冷启动接线补充：已确认并实现

用户已确认 RESTART_AND_MEMORY_CHECKPOINT_PROPOSAL.md 的两项改进。用户已选择命令准备后等待下一条真实输入；这里补齐原提案明确留下的命令触发与恢复定位决定，不重复讨论已确认的核心方向。

实现和实际验收见 RESTART_AND_CHECKPOINT_VALIDATION.md；以下保留已确认接线及取舍依据。

## 第一部分：目的、范围与取舍

推荐增加原生无参数命令 /memweave-restart，只在启用 MemWeave 时注册。命令本身不调用模型推理：先在当前 Session/分支记录冷启动范围、退出旧绑定并取消旧窗口积压，随后等待下一条真实用户输入；Agent 据此生成新 Goal 并创建新 Task。新输入仍是真实事件。旧 Task/State/Session 和其他会话不删除、不暂停、不重编号；已有配置不改。确定自动 N/B 时可能复用既有模型容量元数据查询，不发推理请求。

该选择避免为了立即启动而新增一条持久化程序消息或伪造用户消息，也不自动产生一次模型调用。代价是命令完成后需要用户再发一条工作要求。命令准备范围中没有用户时，仍执行已确认的“最近用户＋N-1尾部事件”选择；整个分支没有用户则等待用户输入，不猜目标。

另一方案是命令完成后立刻运行 Agent：需要通过 Pi 原生 custom message 触发，并给该新消息定义来源核验、事件计数、恢复和预算语义。它更即时，但增加模型可见协议及自动 API 调用，本轮不推荐。

## 第二部分：技术接线与恢复记录

- 新增命令而不新增模型工具，不给 Agent 通用清空/重置权限；空闲时执行，有原生排队输入时拒绝，避免抢走已在执行的要求。重复调用尚未完成的冷启动不产生另一套任务。
- 沿用 scope/window 的原有职责；新增 Pi custom 类型 memweave.restart.v1 保存轻量冷启动意图，仅含 restart_id、previous_task_id、anchor_entry_id、seed_event_ids、recent_turns、evict_turns。ID 指向当前分支的原始消息/完整事件，不保存消息正文或新增聊天副本。
- scope 仍只保存原 task_id/六字段覆盖，Window v1 仍保存既有批次。冷启动定位为它们定义初始选取序列：种子完整事件＋锚点之后新增的原生事件。正常请求仍执行 N/B；参数显式变化时回到既有“从原历史重选”语义。补入较早用户不能被扩展成额外永久锚点。
- 命令、请求、工具前均核验恢复记录与当前分支来源。退出旧绑定/取消 pending 的部分写入必须恢复同一意图，不以仅内存成功为准。新 Task ID 在该 Session 的同一冷启动意图下稳定；Goal 仍使用既有 update_goal 初始记录和真实 task_create 调用来源，State 不保存新字段。
- 若 Goal 已提交但索引/绑定失败，下次请求先根据原始调用及已提交 State 修复同一候选 Task，不重复生成 Task 或改写初始 Goal。新绑定提交后退出“待建 Goal”状态。fork/tree 按原生祖先链恢复；新 Session 的独立冷启动候选不共享未完成创建事务。
- 新格式只由新扩展识别，不宣称旧 MemWeave 版本可读取此新流程；既有数据仍按原契约读取。验收继续覆盖 Pi 1.3.0/1.4.0，不修改宿主。
- 阶段记忆检查按已批准提案加入固定 Rule，不以 turn_end/stopReason 自动推断阶段、不新增工作流状态或自动生成 F/D。

按确认内容先同步 Task/Window/Rule/State 的直接相关规范，再补命令、26000历史恢复、用户补入、来源/配对、重试/重启/分支/部分失败、真实 DeepSeek 与分发回归。没有新增落盘正文或跨进程全局当前 Task。

### 接线的确定细节

命令仅在空闲且无排队输入时接受，参数非空拒绝。完全没有原生 user/assistant 的空 Session 不强迫 Pi 落盘，也不追加仅内存的恢复记录，直接等待首条用户输入；已有对话但无 user 时可以准备种子，仍须等待命令之后的真实输入才推理。重复未完成冷启动复用原意图。

restart 记录是退出旧绑定的恢复意图；随后追加既有 scope(task_id=null)，继承 overrides。若这一步失败，新读取器仍以该意图视为未绑定，并在重启后的请求前补齐；不加载旧 State。已有旧 Window 快照被此意图隔离，第一请求只从种子完整事件＋锚点后事件建立既有 prepare/commit 序列。首次完整种子仍按 N/B 处理，加入新事件可能像普通窗口一样临时超过 N；不会重新纳入旧积压。实际 N/B 变化沿用从完整原历史重选，或边界已越过种子后恢复普通连续选取；补入用户不永久常驻。

候选 Task ID 由当前原生 Session ID 与 restart_id 稳定生成，存储 workspace 使用原生 Session cwd 身份，避免重开时 SDK cwd 不同生成第二份文件；State 的初始 op_id 仍来自实际 assistant entry/tool call。候选 State 已提交时，先核验原调用、修复同一 Task 的派生索引/绑定，再发送下一请求；只读取既有 Goal，不重新生成或覆盖。task_create 的旧调用幂等重试按该调用当时的祖先冷启动意图定位。不能从不明原文或损坏状态猜回 Goal。

Seed 的 N/B、事件顺序、完整工具配对、最近用户补入及锚点必须逐次按当前分支原件核验。历史所属 Task 不改变，只有冷启动后未绑定的触发用户及创建轮按既有规则进入新 Task。明确取消冷启动而恢复旧 Task 可以使用既有 task_resume；不静默回退新已提交认知。
