# 阶段 4：原文回读与来源恢复边界（已确认）

日期：2026-10-21。用户已批准本提案；先增量更新直接相关的规范，再实现。

## 第一部分：目的、范围与取舍

目标是让模型能够按已知引用读回原文，包括离开窗口的消息、其他 Task 的证据和 Pi 截断过的大输出，并且明确区分“只返回了一部分”与“原件本身已经缺失”。不增加搜索工具，不切换 Task，不改写 State 或原始 Session，不提前开启 Recent Window。

当前 U/A/T 定位已经完成，但规范尚未定义 R 别名的产生入口、持久化结构，以及图片和多块正文的回读口径。推荐统一以下边界：

1. **跨 Task 回读时允许明确指定来源 Task。** 给 `memory_read.items` 增加可选的 `task_id`：省略时仍读当前 Task 的 U/A/T 或 R；指定其他 Task 时，只读那个 Task 中已经存在的 U/A/T，成功定位后返回当前 Task 可复用的 R 别名。模型必须已经知道来源 Task 与引用，不接受模糊查询。优点是只扩展已有读取工具，来源清楚，`state_read` 保持读取认知的职责；代价是增加一个可选参数和少量别名元数据。
2. **R 与大输出定位继续存入 Pi custom 元数据，原文仍只保留必要的一份。** 普通消息读 Session；确有临时完整输出时，按哈希保存到既定 `blobs/`，防止系统清理临时文件后丢失。图片已在 Session 中时直接定位该内容块，不重复复制。别名按 Task 分配，多个 Session/进程共享编号，重试不产生第二个别名。代价是首次读取可能登记元数据；大输出占用额外磁盘，禁用/卸载扩展不自动删除。
3. **字符偏移有统一口径，缺失和截断分别报告。** 按 Unicode 码点计字符，多块正文按原顺序拼接，以换行分隔，CRLF/CR 统一成 LF，不去空格、不做 Unicode 归一化。返回正文受统一字符预算限制；一条失败不遮蔽其他结果。推荐默认总正文 8000 字符、硬上限 50000 字符，这只是回读工具的安全限制，不改变上下文半额预算。回读返回可读正文和来源信息；工具调用参数、推理和签名继续保存在 Pi Session，不拼入回读正文。
4. **图片明确读取时才发送原生图片块。** 读取 U/T 的文字时返回附件 R 引用；随后明确读取那个 R，且实际模型支持图片时，才返回 Session 保存的完整图片块。图片不切 base64，另设单次合计 10 MiB 上限；不支持或超过限制时明确失败，不声称看过图片。其他不能文本解码、Pi 又没有可发送内容块的二进制格式，返回不支持状态及来源信息。不会把二进制伪装成文字原文。Pi 只保存了缩放版本时，不能声称找回上传前的原图。

其他可行方案是让 `state_read` 自动为历史 State 的证据分配 R，避免新增参数。但它会让认知查询承担原文别名登记，也无法直接读取已知但未写入 State 的旧消息；不推荐作为唯一入口。仅在进程内保存 R 更简单，但无法满足重启、跨 Session 和并发恢复要求。

上述方案不改变 Goal/Fact/Decision、现有 State 事件格式、U/A/T 编号、Task 绑定或 Pi Package 发布方式。完整回读在紧接着的请求及其网络重试中豁免普通截断的接线，随阶段 5 的统一预算实现；本阶段登记可核验的回读结果，不能宣称已经实现完整 Q 预算。

## 第二部分：技术细节

### 规范依据与缺口

- Task 规范 §5.2 要求跨 Task 原文以当前 Task 的 R 别名读取，但没有定义从已知来源到首次 R 的入口；State §9 的 `memory_read.items` 目前只有 ref/offset/limit，没有来源 Task 参数。
- State §9 写“程序此前分配的跨 Task／外部原文别名 R”，但 Task §8 已确认的 `memweave.references.v1` 只包含 U/A/T，未规定 R 的记录结构。State §14 也明确将 R 留到后续阶段。
- State §9 将 offset/limit 定义为“规范化后的文本字符位置”，没有明确 Unicode 单位、多块拼接和非文字内容的返回方式。
- Recent Window §6.2 要求图片／二进制默认使用原件引用，明确读取且模型支持时才能完整发送；§7 要求将必要的临时原件按内容哈希转存 blobs，但没有规定关联元数据。

### 输入与结果

保留现有输入，增加 `items[].task_id?: string`。R 始终属于当前 Task；指定其他 Task 时输入必须为该来源的 U/A/T，不跨 Task 解释 R，不允许 F/D 冒充原文引用。调用必须有当前 Task；同一 assistant 轮混合 Task 切换与 memory_read 时拒绝冲突，避免读取/登记落到不确定的当前 Task。

输入数组要求非空；offset 为安全的非负整数，limit 为安全正整数；max_total_chars 默认为 8000，最大 50000。预算按请求顺序分配，只统计返回正文，不把失败说明充当原文。没有剩余预算的条目明确标记，不能跳过后伪称整批完成。

每项结果包含输入 ref、当前 Task 可复用的 ref（跨 Task 时为 R）、source_task_id、原来源 ref、content、实际 offset、total_chars（完整原件可得时）、truncated、source_complete 和 status。range_complete 单独说明请求范围是否完整返回；即使原件不完整，也不能仅因本次片段读完而报告完整原文。来源 Session/entry/native tool call ID 作为定位信息保留。

正文从原始 Session 条目提取，不能从请求里加过引用头、截断过或被 context_edit 改写过的展示文本恢复。普通消息规范化仅处理 text 块；assistant 的工具名/原生调用 ID 作为来源信息返回，工具 arguments、thinking/signature 仍保留在原始 Session，不把它们拼入正文或暴露为普通思考文本。遇到不能解释的内容块明确报告，不默默丢弃后声称完整。

### 别名与原件定位

沿用 Task 写锁，在该 Task 已登记的 Session 中读取并校验元数据：

- 新 custom 类型 `memweave.aliases.v1`：`{task_id, bindings:[{ref, source_task_id, source_ref, part_index?}]}`。ref 为 R；source_ref 为原 Task 的 U/A/T；part_index 仅用于 Session 内容数组中的附件。R 不指向另一个 R，跨来源别名先解析为最终 U/A/T，避免循环。
- 新 custom 类型 `memweave.originals.v1`：`{task_id, bindings:[{ref, source_session_id, entry_id, blob_hash, media_type, byte_length}]}`。仅登记有额外完整输出的 U/A/T，首个适配目标为原生 Bash 的完整文字输出；不改现有 references.v1，不写正文副本到 custom。

同一来源/同一附件只分配一个 R；编号按全部已登记来源继续，fork 复制不重复分配。原件先可靠写入内容寻址 blobs，再追加 custom 并验证落盘；失败不发布可用别名，不回退为“完整”。崩溃可能留下未被引用的 blob，本阶段不自动清理或删除原始文件。

Bash 完整输出使用实际 Pi `details.fullOutputPath`，在结果落入 Session 后、下一次模型请求前及时转存，并在 turn_end/恢复时补验；不从消息中的任意路径字符串猜测原件。仅看到截断内容而没有可靠原件时保留可读片段并报告 source_complete=false。不能重新读取当前业务文件来冒充历史工具当时读取的内容。默认不为小消息、所有工具结果或已有 Session 图片建立副本。

R 作为 State evidence 时需验证最终 U/A/T 或附件实际存在；来源缺失不能仅凭别名记录当作证据存在。不会把 R 分配记录本身变成新的事实依据。

### 图片与预算衔接

读取 U/T 的正文时返回独立附件列表，其中的 R 定位原 Session 的 image 块。直接读取该附件 R 表示明确要求原件；不接受字符 offset/limit 对图片切片。模型不支持图片、图片损坏、来源缺失或超过字节上限时返回对应状态，不发送部分 base64。文本字符预算与图片字节上限分别校验。

工具结果保留机器可核验的成功范围及附件定位，阶段 5 据此把最近一次显式回读计入 X。只有程序登记的实际回读结果适用，正文自称“完整回读”不能获得豁免；网络重试不消耗，后续新逻辑请求恢复普通策略。

### 修改范围与验收

确认后最小更新 Task §8、State §9/新增阶段 4 约定、Recent Window §7 的来源适配说明；固定 Rule 只在确需说明可选来源参数时同步两处及生成资源，不改核心记忆思想。

主要代码范围：`src/memory/` 的 schema/规范化/读取/别名与原件服务，`src/pi/` 的来源与工具结果适配，`src/storage/paths.ts` 的 blob 路径，必要的二进制原子写辅助，以及扩展工具注册、Task 引用证据校验的接线。

先写单测与 Pi 集成测试：Unicode 与边界、顺序总预算、坏引用部分成功、原件不完整、Task 隔离、R 重启/fork/并发与重试、大输出临时原件删除后仍可读、blob/元数据写失败、图片能力与完整块、原始 Session 未改写。再用仓库外私有 DeepSeek 配置验证真实文字回读闭环；图片真实供应商调用不冒用文字模型验证结论。临时 Session/文件在系统临时目录，失败与成功均清理。通过后形成阶段提交并推送。
