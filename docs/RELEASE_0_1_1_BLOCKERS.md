## 第一部分：发现、影响与建议

基础程序链路通过，但额外真实 DeepSeek Flash 专项反复出现输出不符合预期，不能把完整自动入口的一次成功当作全部发布条件满足，也不能重试到绿后隐藏此前失败。

1. **最新要求有时被旧要求盖过。** 测试先故意用小预算取消两条输入，再恢复预算发送第三条。真实出站内容包含三条原文，第三条有唯一 CURRENT_USER_MESSAGE 标记；仍出现回答 FIRST 或 SECOND 而非 THIRD。短测可通过，重新运行又可失败。尚无消息丢失证据，问题体现为模型没有稳定执行优先级指引。
2. **业务完成不一定留下新认知。** 一个真实临时组件修复用例已完成设置与验证，却没有调用 state_append，State 只有 Goal。另一次模型把要求的精确超时值 118 改成工具允许的最大值 10000，没有达到夹具验收标准。诊断复测又可按要求执行并保存证据，不能因此宣称问题已解决。
3. **部分工具流程也有单次失败。** 一次解包恢复只有 v2，预期的事实未追加到 v3；一次盲读图片的最后请求没有图片。各场景在其他运行中通过，后两次失败缺少足够原始诊断，不能断言统一根因或伪称已经修复。

推荐先增强现有模型指引，再重新验收。核心仍是模型决定重要认知并调用现有工具，不引入自动保存、摘要 Agent、额外推理、阶段状态机或新的持久化字段。加强指引只能提高遵循率，不能承诺模型永远正确。

可选范围：

| 方案 | 优点 | 代价/结论 |
|---|---|---|
| 继续只使用当前长 Rule 和工具描述 | 不修改当前候选 | 已复现漏记和优先级错误，不推荐直接作为稳定版上传 |
| 在末尾 State/预算旁加入简短常驻执行检查，并精简相应 Rule 指引 | 把已有要求放在模型更容易注意的位置，维持现有设计；推荐先验证 | 每次请求增加少量提示 token，需要同步请求协议、预算计量及两份 Rule；效果仍需真实验证 |
| 程序判断阶段并强制自动写认知/补推理 | 可增加强制检查 | 改变已确认的核心思想及调用成本，不在本次推荐范围 |

> 本消息是程序状态。最新真实要求在 CURRENT_USER_MESSAGE 标记处；冲突时遵循该要求，兼容的旧要求保留。准备交付时，先核验业务结果，再检查尚未保存在 State 的重要新认知；需要保存则先提交既有工具并核对回执，无重要新增不写。未成功回读的原件不得猜测。
