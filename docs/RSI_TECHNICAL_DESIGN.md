# RSI 自进化实验系统技术方案

## 2026-11-21 递进小批次与统一实验入口

本版把已有实验转成一个可反复研究的题池。每道题保留原题版本、两侧实测结果、评测协议和原件位置。以前的回归、训练、普通验证、困难验证四个分组用于追溯历史。研发者可以阅读过题与未过题的题目、实验经过和已有复盘，寻找通用机制上的原因。被测 Agent 在独立沙箱里接收当次原题输入，裁判在外部判分。只有实验维护端持有模型凭据。

### 节点如何进化

1. 一次开发的产物形成一个冻结节点，记录来源节点、参考过的分支、实现和改动理由。同一节点的三轮测试使用同一产物。任何代码、提示或实质配置修改都形成新节点。
2. 以冻结的参考插件逐题分成过去通过、过去未通过两组，原生成绩单列。每批各抽一半，同一候选三批互不重复。新节点重新抽样，优先近期少抽的题。三批可从 **4、4、8** 道起步，连续成功共测 16 道，至少需要 8 道不同的已确认未过题。未知、单纯的环境故障及缺终态的题先补测。保存抽样依据、实际题单、参考版本及逐题结果，使同一次中断可以续跑。
3. 每批在完全相同的题上与该参考插件比较。候选通过数净增至少 1 题才进入下一批。比如第一批原来过 2 题，新过 1 题又丢 1 题，仍是 2 题，本轮失败。三批都成功，把该节点固化为当前最好，下一次从它出发开发，回到第一批。任一批失败，保留节点与实验经过，下一次开发也回到第一批。Agent 可以结合任务完成情况、调研与反思，从当前最新 Top 3 或最近固化节点选择父节点。连续三次在第一批失败时，明确要求另起新根或选另一分支最近固化的节点。图上分开记录代码父节点与成绩比较对象。
4. 候选必须从底层机制作通用改进。禁止按题号、题面指纹、仓库或答案特征分支，也禁止把这类特判放进启动适配器或共享记忆。随机抽样降低反复调同几道题的风险；“当前最好”表示该节点在记录的批次上连续改善。已供研发阅读的题，其成绩按已见题报告。

本次以现有已冻结插件的成绩整理基线，优先补插件未知的难题。新固化节点若在某题没有可比较成绩，保留版本和“待测”，旧节点成绩保留其原有归属。不同题单的 Top 3 排序留到实现进化调度时确定。本阶段只建设实验环境、整理原题证据并补测剩余难题。

2026-11-21 后续工作集中于难度筛选和额外难题。优先标定已有原生三次有效未过、参考插件仍待测的原题，再根据实际失败记录和原题要求补充候选。作者给出的专家耗时、形式化证明或科学计算要求用于筛选候选，正式难度以冻结参考插件的有效实测结果判定。模型预算用于这些候选的难度标定，已有环境与成绩继续直接复用。

### 题目环境与 Agent 如何连接

题目侧固定原始输入、执行镜像、原题权限与资源、交付方式及官方裁判。部署在评测端的适配器选择受信的 Agent 实现，并将候选及运行配置交给 Harbor 的安装和执行入口。控制器负责模型代理、总资源预约、停止、计时、收集交付物和结果入账。适配器不根据题目身份改变候选行为。Agent 内部的记忆、工具编排和调用方式可演化。

原题声明的辅助服务由评测端按原件接入。维护端逐项绑定声明摘要、已核验镜像、内部端口和原题资源。每次运行独建私有网络供本题工作容器访问服务，独立裁判和模型凭据留在各自的隔离边界内。服务运行期间计入资源预约，退出时核对容器和网络已回收。辅助服务有改动时，只复验该服务的原题客户端、隔离和回收，复用其余可核对的实验原件。

原裁判若明确使用非 root 子进程读取交付物，传输适配须保留这种读取能力。仅对原题声明、同一答题容器已提交且摘要相符的文件，向原裁判声明的身份授予读取和父目录遍历；不授予写入。按原标准解与空解复验受影响的交付路径，模型结果仍独立记录。

镜像依赖清单使用公共的只读检查：确认 Python 解释器和 pip 是否存在，有 pip 时读原 pip 清单，缺少 pip 时通过原解释器的 `importlib.metadata` 读取。原镜像确无 Python 时明确记录缺失，无法执行检查或输出无效时报告错误。该检查不安装软件；原标准解与空解仍负责验证真实题目能否运行。

公开网络的启动预检沿用现有最多三次检查。仅在模型代理已正确拒绝无凭据请求、固定公网目标全部出现明确的暂时连接故障时重试；保留每次检查原件，仍用同一检查程序、超时和通过条件。认证、隔离或不完整的检查失败直接报错，耗时继续计入原累计预算。此修复只验证受影响的联网路径，复用原裁判对照与已有题目成绩。

| 改了什么 | 复用什么 | 最少需要核对什么 |
|---|---|---|
| 只改候选 | 原题、镜像、交付物、裁判与已验正反对照 | 核对新包、实际加载和一次通用输入输出。候选自己的模型成绩按新版本记 |
| 改启动或交付方式 | 身份与语义相同的题目材料、原裁判和软件缓存 | 按实际受影响的运行方式验证输入、交付及中断；可用确定性提供方 |
| 原题、镜像、裁判、资源或隔离语义改变 | 逐项复用仍可验证的独立材料 | 重新验证受影响的原题环境、标准解与空解，并记录新配置的可比范围 |

整理和续跑以正式账本为准。已通过的题直接登记；已有有效失败也直接登记。只给缺少有效结论的难题分配新工作，环境资格、逐题模型成绩、两侧差异分别列明。原题时限、最多三次有效尝试、累计活动预算、凭据隔离、未知费用和缺终态处理仍按实际运行所属协议执行。总体预算开放。原试点和旧 100/200 题的历史记录继续使用各自协议复核。

## 1. 目标与不可覆盖原则

本期由单一进化 Agent 主动深入调研、搜索、分析训练失败，从第一性原理定位底层机制，提出改动并形成独立候选。允许研究架构、实现、prompt、工具、Task、State及上下文窗口，或从原生Pi建立新根；研究范围不构成改动产品定稿规范、权限边界或真实评测协议的自动授权。

**禁止题目特异性特判或针对性调参。** 禁止依据题ID、数据集、仓库、题干指纹、输入／答案特征选择专用逻辑、参数、prompt、缓存或答案；也禁止用看似通用的规则包装对单一题目或数据集的过拟合。此原则不可由训练涨分、审批、验证结果或后续候选的自述覆盖。

每项机制改动都必须建立可审查的证据链：**失败证据 → 被破坏的通用Agent不变量 → 最小反例及对竞争解释的排除 → 机制改动 → 可复现的跨题族迁移、消融和防退化证据**。最小反例、消融及迁移检查应独立于官方题目和评分器保存，不向原题插入hook；不得使用隐藏验证证据完成这条研发证据链。分数上涨本身不能通过通用性门禁。

禁止更改题面、原题资源要求、评分器、官方答案、原始记录或账本来制造收益；禁止读取、反馈或通过摘要／共享经验泄漏验证隐藏证据。现有真实资源准入、停止、未知用量及缺终态HOLD约束继续适用。

## 2. 固定题集与有效尝试

新题集共80题，使用独立的新清单、版本和摘要，不覆写或重新解释旧100／200题清单。三组题目身份互不重叠，尤其回归与验证不重叠；具体原题清单尚未选择或冻结。

| 集合 | 数量与难度 | 用途与可见性 |
|---|---|---|
| 功能回归 | 20道简单题 | 检查基础功能和退化，按审批后的候选执行；结果可用于修复，不计作训练或验证收益 |
| 训练 | 固定20道难题 | 题目及获准失败证据对进化Agent可见；在同一组题上反复研发、训练和改进 |
| 独立验证 | 40题：20普通＋20难 | 由独立评测端运行；验证评分与逐题证据不回流进化Agent |

训练难题组和验证难题组各自的**入选难度门槛**为：冻结标定版本和同一协议，每题最多三次有效尝试、首次通过停止后，该组通过率严格低于50%，即各自最多9/20。它是两组分别满足的题集入选条件，不是晋升阈值，不是逐题难度标签，也不是两组合并低于50%。标定主体及协议须在选题前固定，不能据候选后续成绩重新挑题。

每题最多三次有效能力尝试，通过即停；网络／环境故障和用户中断不占有效尝试，物理执行序号和真实耗时仍保留。通过率分母固定为20或对应验证组20，完整验证为40；未完成、HOLD或待资源不缩分母、不当作已通过，也不提前作出完整晋升判定。有效尝试的官方证据、累计实际执行计时和同版本续跑边界须在评测协议中固定，沿用已批准的原件保全和单调计时原则。

## 3. 父版本、对照基线与训练门禁

代码父版本与收益对照基线分开。进化Agent可以选择未晋升、失败或未判定候选为研发父节点，也可选已验证版本或原生Pi新根；比较对象始终为当前最佳**已验证插件基线**，不能因为选了较弱父版而降低比较门槛。

新题集的初始参考插件必须先在新20道训练题上按同协议标定；初始版本的已验证资格与基线登记程序也必须明确。旧题分数、旧题通过复用证明、旧100题首轮插件结果均不提供新训练分数。初始基线未合格建立时，候选不得借用旧分或把自己宣布为最佳已验证版本。

对候选C和固定基线B，只在训练题集、模型／运行时、原题资源、裁判、计时、有效尝试及汇总规则相同且证据完整时比较：

`training_passed(C) / 20 > training_passed(B) / 20`

必须严格大于，持平不合格。在20题固定分母下至少多通过一题；不得选取有利子集、重置同一冻结候选的三次机会、挑多轮最好分或通过更换基线规避门禁。代码或评测实质身份变化形成新的冻结Candidate，历史尝试完整保留。

**只有训练严格改善且通用性审查通过，才能提交审批。** 训练改善仅是提交资格，不登记真实验证收益，也不晋升最佳插件。基线、题集或协议变化须重新比较和审查，已有审批不能挪用。

## 4. 主动研究与通用性审查

每轮先审阅全图允许公开的摘要、历史经验和相关代码，深入搜索、调研相关研究和工程证据，分析失败的因果机制。记录资料来源、适用条件、研究方案、可推翻假设的观察和竞争解释；不得只围绕当前题目的补丁形状做局部调参。

保留既有选点读取门禁：选父节点或新建节点前，至少读取8个不同节点的原始代码与相关获准信息，同组Top5全部读取、其外至少3个；节点不足8个时不强求数量。程序须核验读取记录。Top5只使用可公开的同协议训练证据形成，不按隐藏验证分数或逐题结果向Agent提供排名。

通用性审查须逐项确认第1节证据链，并检查至少以下问题：机制是否由通用不变量导出；最小反例能否复现；竞争解释是否已排除；跨题族迁移是否可复现；消融能否区分机制作用；防退化证据是否充分；是否出现题目／数据集指纹、针对性参数或隐性答案选择。证据不足应拒绝提交或标为未判定，不以涨分替代审查。

迁移和消融可使用获准训练证据、公开材料及独立构造的检查，不得偷跑或反复探测独立40题验证集。额外真实运行须遵守执行授权，本次文档更新不授权这些实验。

## 5. 版本审批与回归

提交审批时冻结候选源码与产物、训练结果、通用性审查及对照基线。审批必须绑定精确Candidate版本／产物摘要、基线身份及其证据、题集与评测协议摘要；记录审批者、范围和决定。进化Agent不能把自行提交当作审批通过；审批不授予读验证隐藏证据的权限。

批准后顺序固定为：**先运行20题功能回归，回归通过后再独立运行40题验证**。保留原生Pi基础功能检查，不能用其替代20题回归。回归通过判据须在正式协议中冻结；不得沿用旧文档示例的10个百分点容差自动放行。

回归未通过时，将获准回归结果反馈进化Agent继续修复；修改形成新Candidate，必须重过同组20题训练的严格改善门禁、通用性审查和审批，再测20题回归。不得沿用旧候选审批，也不得修改冻结产物后继续其验证。审批仅覆盖原样候选的同协议、未增加有效机会的证据完整续跑；实质版本、基线或协议变化均须重新审批。

## 6. 独立验证、真实收益与晋升

独立评测端使用审批绑定的原样产物与固定基线，在相同40题和协议下比较；普通20和难20分组保留，不能用总分掩盖其中一组的变化。验证评分与逐题证据，包括通过率、分组分数、逐题成败、日志、答案、补丁和裁判输出，均不回流进化Agent、其工作区、全图摘要、共享经验或周期性总结。

进化Agent只接收控制面允许公开的流程／晋升状态和基线身份；研发侧不获得验证评分或失败定位。用户及受信评测审计端可查看完整私有证据，其权限不传递给进化Agent或记忆发布链。

**仅验证通过的候选可以登记真实收益并晋升最佳插件。** 即使训练改善、回归通过或审批完成，只要验证未过、未完成、HOLD或尚未判定，就不得登记已实现收益、替换最佳基线或自动视为成功。晋升须保留基线前后身份、完整比较及审查／审批／回归／验证证据。

验证通过的量化规则尚待正式冻结。**建议默认值（未获确认，不得执行为正式门禁）**：相对同协议固定基线，普通20题通过率不退化，难20题通过率严格改善。旧5个百分点／token节省20%的晋升判据不适用于本版；token、时间和费用仍完整存档，但不能单独换取晋升。

验证未过或未判定的候选完整存档，可作为下一轮研发父节点；不向Agent提供隐藏分数或逐题失败原因，下一轮仍以最佳已验证插件为对照。相同候选验证的次数、复核及重验边界须预先冻结，不能靠反复隐藏验证挑最高分。

## 7. 对象关系、版本与证据保存

保留 `EvolutionJob → Candidate → Experiment → Run`，不将一次研究、源码版本、整组评测和单题物理尝试混成一个节点。
