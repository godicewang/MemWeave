# RSI 自进化实验系统技术方案 v2

本文整合已对齐的两版方案，描述设计目标，不代表系统已经实现。本期使用一个 Codex CLI 进化 Agent，保留未来多 Agent／多队扩展能力。

## 1. 目标与范围

进化 Agent 可基于任意版本的插件代码，自主修改架构、实现、prompt、工具、Task 分支、运行时持久化、State 和上下文窗口，也可从原生 Pi 新建根节点，重新设计为插件、hook 或其他形式。

每次进化均为一个节点，成功、收益未达标和失败节点都保留代码、摘要、思路及复盘。实验继续使用未改动的原题和已有环境，不使用此前修改或加入 hook 的题目，也不沿用旧指标评分体系。

## 2. 回归、能力测试与成功条件

每题最多进行 3 次独立尝试，首次通过即停止；任一次通过，该题即通过。通过率为通过题数／题目总数。

回归测试分两类：

1. **Pi 原生基础能力回归**：检查原生能力与基础功能是否正常。
2. **基础题目回归**：使用 Pi 和插件本身都能通过、覆盖不同场景与难度的题目，只做回归门禁，不打分。通过率可比同组当前最好插件低最多 10 个百分点，例如 80% 降至 70%。

任一类回归未通过，结果反馈给进化 Agent，在同一节点继续修复，直到两类均通过；Agent 可以读取回归记录和结果。

回归通过后，以大量不同类型、不同难度的题目做能力／收益测试，直接计算最终通过率。固定候选版本、题集、裁判、模型配置及尝试规则；比较基线为同评测组中通过率最高的插件版本。

满足任一条件即进化成功：

- 能力通过率比基线高至少 **5 个百分点**。
- 能力通过率比基线低最多 **5 个百分点**，且 token 消耗减少 **超过 20%**。

Token 计实际执行的所有尝试的输入与输出，包含失败尝试；首次成功后的未执行机会不计入。收益未达标节点仍然保留，并可成为后续研发的父版。

## 3. 选点与研发

每轮先审阅全图摘要、历史经验和相关节点记录，按需核对源码与原始证据；调研最新相关研究，形成研究方案，记录候选比较、选择理由、预期收益，以及能推翻假设的观察。

优先从同评测组 Top 5 节点选父版，也可选择失败节点、其他可恢复版本，或以原生 Pi 建立新根。选择由进化 Agent 决定；历史节点研发必须基于其精确 commit，新根不依赖历史插件代码。

## 4. 代码、尝试与节点保存

平台与进化代码分仓，宿主管理共享 Git 对象库。每次开发或修复从精确版本创建独立的 detached worktree，同一节点只有一个写入者。

研发完成后停止写入，冻结源码和产物，再执行回归。回归失败时保留同节点尝试链，从对应精确版本继续修复；通过后，为同一候选 commit 建立永久节点 ref，并用已验证产物进行能力测试。

SQLite 关联节点、开发／修复尝试、评测批次和复盘。中止时保留最后可核验检查点及记录，不把未完成阶段标成成功。

## 5. 上下文、证据与复盘

进化 Agent 启动时载入目标、评测契约、全图摘要、已发布共享经验、周期指导和自身摘要；按需检索历史源码、计划、结果、日志、复盘及获准公开的证据，证据可按 ID、行号或哈希定位。

评测端私有能力题库、答案、裁判和凭据与进化 Agent 隔离；被测 Pi 每次只接收当题输入。其他队的私有会话及工作区保持隔离，本期只预留该扩展边界。

复盘分两层：

- **节点复盘**：记录假设、实现思路、改动证据、相对基线变化、结论与反例、失败原因、未知及后续验证；附在节点上，按需阅读。
- **共享经验**：记录通用结论、适用条件、反例、建议及证据，经独立审计后由宿主版本化发布。新任务加载已发布版本，续跑沿用已绑定版本；多队冲突处理保留扩展能力。

每新增 10 个首次回归通过并封存的节点，进行周期总结，包含收益未达标的节点。晚到信息补审，过时经验限定适用版本或退役。

## 6. 一轮完整流程

1. **选点**：审阅全图、核对证据、研究并比较候选，确定父版或新根及研究假设。
2. **研发**：从精确版本开发，保留尝试与代码，冻结候选源码和产物。
3. **回归**：执行两类回归；未通过则反馈并在同节点修复，直至通过。
4. **收益测试**：为通过回归的候选建立永久节点 ref，使用已验证产物执行固定能力评测。
5. **判定与复盘**：按通过率／token 条件判断进化是否成功，写节点复盘与共享经验，按周期更新指导。
6. **完成**：保留节点、代码、评测与复盘；失败或中止也保留可核验记录。
