# RSI 自进化实验系统技术方案

## 1. 核心目标

让 Codex CLI Agent 可以完全基于任意版本的插件代码，自主修改插件的任意代码，包括架构、实现、prompt、工具、task 分支、运行时持久化、state 和上下文窗口。

## 2. 测试与进化成功条件

### 2.1 回归测试

回归测试分为两类：

1. 最基础的能力测试：检查 Pi 原生的能力是否仍然满足，基础功能是否正常。
2. 基础题目回归：使用多个 Pi 和插件本身都能通过的题目，检查是否仍能完成不同场景、不同难度的基础题目。这类题目只做回归性测试，不做打分。

每个题目给 3 次独立的重试机会，三次通过一次，这个题目就算通过。

整个回归测试的通过率达到一个阈值即可。例如，插件当前最好版本为 80%，只要低于这个值不超过百分之 10，即算通过。

### 2.2 能力测试

通过回归测试后，使用大量不同类型、不同难度的题目进行能力测试，直接计算最终通过率。

每个任务有 3 次尝试机会，三次通过一次，就算通过。

满足以下任一条件，算进化成功：

1. 通过率达到“≥当前最好版本的插件 5%”。
2. 通过率“不低于当前最好版本的插件 5%”，同时 token 消耗有超过百分之 20 的缩减。

历史上没有通过进化的节点也需要保留。

## 3. 进化节点、记忆与代码保存

每次进化算作一个节点，失败的也算。每个节点都需要保留对应的代码，以及摘要信息、思路和复盘等内容。

进化可以基于一个全新节点，也可以基于某个历史节点：

- 全新节点允许以原生 Pi 为基础，完全重新写一种新的形式。形式不限，可以是插件、hook 等。
- 选择历史节点时，优先选择最佳的 top 5 节点，也可以选择失败节点，由进化 Agent 自主决定。

复盘信息分为两部分：

- 关于本节点实现思路、问题等的复盘，附在本节点上；进化 Agent 阅读相关节点时自行阅读。
- 关于通用踩坑或能力方面的信息，写入通用复盘知识库；下次进化 Agent 启动时，自动载入其上下文。

## 4. 一次完整进化的流程

### 第一步：选点

进化 Agent（Codex CLI）先审计整个进化过程中所有节点的历史消息，总结经验；然后调研当前最新的相关研究，给出研究方案。

随后，进化 Agent 自主选择重建一个全新节点，或选择一个历史节点作为本次进化的基础。

### 第二步：开始研发

如果选择历史节点，必须在选中节点对应版本的代码基础上开始研发，生成本版本代码。全新节点不需要基于历史节点代码。

### 第三步：回归测试

完成开发后，进行 Pi 原生能力回归测试和题目基线准确率回归测试。

两类回归中的任意一类未通过，就将结果反馈给进化 Agent，让其继续改进，直到通过。进化 Agent 可以阅读回归测试的实验记录和结果。

### 第四步：收益测试

通过回归测试后，使用准备好的大量不同类型、不同难度的题目，测试本次改动的收益。

### 第五步：确定是否进化成功并复盘

根据收益测试结果及进化成功条件，确定本节点是否进化成功。

随后要求进化 Agent 完成本节点复盘：本节点的实现思路、问题等附在本节点上；通用踩坑或能力方面的信息写入通用复盘知识库，供下次进化 Agent 启动时自动载入。

### 第六步：完成

完成本次进化，保留该节点对应的代码及相关信息，无论本次是否进化成功。
