# 阶段 5：Recent Window 验收记录

日期：2026-10-22。目标宿主 Pi v1.3.0；Node v24.22.0、TypeScript strict。阶段 5 已完成，阶段 6 的最终兼容／升级／发布验收仍单独保留。

## 已实现范围

- 完整事件索引：一条真实用户为一事件；一次 assistant 与其全部工具结果为一事件，结果顺序和原生关联保留。错误／中断的未完成返回不当作成功事件，不拆分工具组。
- N/B 选取：默认 200/40，首次超限保留待移出内容并提醒；多批积压同次提醒，当前 assistant 与工具完整结束后按序可靠提交，不额外发起模型请求。
- `recent_window_set`：仅作用于当前 Session／分支，下一请求使用新参数、更新 Rule 并从原始历史重选；省略 B 不静默调小，冲突设置明确拒绝。工具成功文本符合规范。
- 半额预算：同一请求快照中渲染 Rule 后计算唯一 Q，完整 State、输出、协议、安全余量、最新用户与本次回读分别预留，M 包括豁免消息。预算失败先 abort，实际 HTTP 不增加。
- 统一正文截断：按 Unicode 码点保留前缀，多文字块共享 Q，不跨过被截断块偷取后续文字。短引用完整，实际省略才追加标记；签名文字、推理、工具 arguments／ID／结果配对保持原样。
- 完整回读 X：核验原生 memory_read 调用、实际范围和机器标记，仅紧接请求及其网络重试豁免；后续回归 Q，图片回归附件 R。普通正文不能伪造豁免。
- Request 布局：有效 system／工具与 Rule → Window → 当前 State（可含 State 管理提醒）→ Window 提醒；后两者是临时 custom，由 Pi 转为 user，不进入 Session 或 N/M。
- 恢复：Pi custom `memweave.window.v1` 保存少量定位；重启、fork／tree、扩大窗口、取消／部分提交失败均按原始分支恢复。旧 compaction 的可恢复祖先记录从原文重新选取，不发送摘要冒充原文。

## 代码与提交边界

`src/window/` 实现事件选取、批次准备、Q 分配、正文渲染、回读豁免、State／提醒布局和 schema。`src/pi/window-service.ts` 连接原生分支、请求来源、Session 元数据和 turn_end；`window-budget.ts` 集中核验输出与图片费用。现有 Rule 请求服务仍只注册一个 context_with_system。

Task snapshot 保留原生分支快照；当前与历史 Task 的短引用沿用已有 metadata，历史消息附来源 Task。memory 内部附件入口复用现有 R 分配与 Task 锁，不增加映射文件或 State 事件。生产入口现有 11 个工具，唯一新增公开工具为已定稿的 recent_window_set。

prepare 持久化的是定位，不是提醒或消息正文。每个 commit 保存前移后的边界及剩余批次；第二批写入失败不撤销第一批，重开后只提醒并提交尚未完成的批次。State 更新是否成功与 Window 提交独立。模板／预算／元数据错误不发送；元数据持久化不确定时，仍要求从磁盘重开，reload 不使脏内存合法化。

开发前已将用户确认同步到 Recent Window §13、Rule §3、架构与提案，并形成检查点 `231bcae`。固定 Rule 正文未改变；技术稿模板、独立模板和发布资源逐字一致检查通过。

## 预算口径与限制

文字目前以 UTF-8 字节数作保守 token 估算，不把它称作供应商精确 tokenizer。H 保留 4096 安全余量；每条消息另留 64 的协议包装估算，U/X 自身包装归入对应项，State 包装归入 S，不重复计数。protected fields 计入固定成本。输出按 Pi 1.3.0 默认 model.maxTokens 及当前有效 thinking level 的 samplingParams 覆盖取值；收紧到剩余上下文的原生机制不作为突破半额预算的理由。模型完整元数据或 thinking level 在准备过程中变化会取消。

budget.total 表示按 Q 分配后的保守上界，不是实际 token 用量或计费。M 包括 U/X，短消息剩余额度不二次分配，因此上界可能明显大于实际请求。

[DeepSeek 官方视觉说明](https://api-docs.deepseek.com/guides/vision/) 当前给出每张图片最多 1024 tokens；官方 Flash 端点每张按 2048 预留，未知模型／端点的视觉费用明确拒绝。真实图像只覆盖 PNG；不能由结构签名检查推断完整解码或推广为所有格式验收。

附件 R 必须具有 Task 来源，因此先以文字建立 Task 再提供图片。未绑定图片会取消并保留原记录，后续可另开文字 Session；不静默发送图片或伪造可回读引用。普通原生工具 read/Bash 已覆盖；用户 ! Bash、自定义消息及未经核验的第三方消息表示会诊断，未宣称任意扩展共存。虚拟路由、强制 system 覆盖、动态工具最终投影及其他 Pi 版本仍待逐组合验收。

本阶段没有正式 npm registry 发布、Git release 或独立应用安装器。最终完整业务升级、多进程同时写同一个原生 Session 文件、其他供应商与高级组合仍属阶段 6 边界，不能由当前通过结果外推。
