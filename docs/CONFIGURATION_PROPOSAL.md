# 配置集中管理提案（2026-10-24，用户已确认）

## 一、目的、改动范围与取舍

把目前散落在代码中的主要运行参数放进可读的默认配置，用户只填写想覆盖的项。默认值保持当前行为；升级时不覆盖用户设置。

建议复用已有运行目录，拆成两份文件：

| 文件 | 用途 | 谁维护 |
|---|---|---|
| `src/config/defaults.json` | 随 Package 发布的默认值，开发时在这里统一调整 | 项目开发者 |
| `~/.pi/memory/config.json` | 用户显式覆盖；只写需要改变的项，可为 `{}` | 用户 |

Agent 已有的 `recent_window_set` 继续将 N/B 覆盖写入当前 Session/分支，不改写源码或全局配置。因此同一机器的多个 Pi 实例不会互相覆盖 Agent 设置。实际优先级为：**包内默认值 → 用户文件 → 当前分支的既有覆盖**。不把用户设置放进 Package 安装目录，也不新增第三份平行配置文件。

用户已确认以下两个边界：

1. **哪些参数现在就允许运行时覆盖？** 推荐开放下表中的策略参数，并严格校验；不只是把硬编码换个位置。另一方案是只集中默认值，运行时仍只支持现有六项。推荐方案方便后续调优，但会扩大配置契约，需要同步规范与模型提示。
2. **Agent 是否可以改动所有参数？** 推荐本轮沿用已有 N/B 工具，其他参数由用户文件覆盖；以后有实际需要，再增加受控配置工具。另一方案是本轮新增通用分支配置工具；它需要增加工具协议及分支持久化字段，不应借本次整理顺便引入。

开放策略配置的副作用：缩小 State 预算、回读期限或窗口会更早触发管理/截断；增大回读预算会挤占普通 Window；调整来源缓存上限会影响内存与命中率。已有完整历史和认知不会被配置文件直接删除。预算不足仍明确取消，不自动裁剪 State、不生成摘要。

**仍保留安全与协议边界：** Agent 总预算不能超过模型容量 60%；来源缓存不能超过已确认的 8192 项/16 MiB；字符/图片回读不能突破现有工具硬上限。Pi 历史所有权、Task/State 类型、证据核验和来源完整比较不作为可关闭的设置。

## 二、技术方案与待确认契约

### 参数目录与当前默认值

下表为推荐开放清单；具体字段命名可在实现时调整，不改变确认后的含义。

| 分组 | 当前默认值 | 覆盖与校验 |
|---|---|---|
| 现有 Recent Window | `recent_turns`、`evict_turns` 均缺省时自动计算 | 兼容已有平铺字段和分支覆盖；有效 B 不大于 N |
| 现有 State | `state_max_events=500`、`state_event_max_chars=100`、`state_evict_batch=100`、`state_keep_limit=20` | 保留字段名；改为缺省继承，而非强制填写 |
| Agent 总预算 | 模型容量 60% | 用户可降低；不得超过 60% |
| 八项预算规划 | State 12.5%、Window 37.5%、输出 10%、系统工具 15%、最新用户 5%、回读 10%、协议 5%、安全 5% | 正值；合计 100%；整数取整余数仍归 Window；安全/输出不借出 |
| 自动 Window 规划 | 最小 20、最大 200、步长 10 个事件；每事件按 2 条消息、每条 256 token 规划；批量移出比例 20% | 正整数及合法范围；已有显式 N/B 优先，不能自动覆盖 |
| State token 管理线 | 规划预算的 80% | 大于 0、不大于 100%；保留上限比例 1/10 仍作为既有协议约束 |
| 完整回读期限 | 后续 10 条真实消息 | 正整数；仍按 user/assistant/每条工具结果计数，不按事件或轮次 |
| 文字回读默认预算 | `memory_read` 和历史 `state_read` 均为 8000 字符 | 正整数、不超过 50000；调用显式参数仍优先 |
| 来源定位缓存 | 8192 项、16777216 bytes | 可缩小或以 0 禁用缓存；分别不得突破上述上限；不关闭完整核验 |
| 模型元数据超时 | 15000 ms | 正整数；取消信号优先，不改 Pi 模型请求重试策略 |

工具硬上限（历史 State 每次 50 项、文字回读 50000 字符、图片回读合计 10 MiB）、缓存定位键长度、tokenizer 校验和、协议标记/版本、文件权限、原子写与锁实现不一并开放。它们可能影响可信性、兼容或恢复协议，不能与普通偏好参数混在一起。必要的固定数值可以集中成有名称的常量，无须把每个内部数字做成配置。

### 文件和合并

- 默认配置随 npm/Git 两条安装方式提供；读取、校验和不可变类型集中在 `src/config/`。用户文件不得回写包内默认值。
- 用户配置允许部分嵌套覆盖，只替换提供的叶子项；不使用会丢失同组其他默认值的浅合并。
- `recent_turns`/`evict_turns` 缺省表示自动，不把包内 200/40 当作用户显式选择。删除用户文件中的显式值且分支没有覆盖后，恢复自动。
- 用户文件不存在时推荐视为无覆盖，使用包内默认值；文件存在但 JSON 损坏、未知字段、非法数字、比例和交叉约束错误仍中止请求，不悄悄回退。
- 不自动覆盖已有配置、Rule、认证、Session 或 State；已有合法六字段文件直接兼容。
- 每个逻辑请求读取一次用户设置，所有模块复用同一不可变快照；网络重试沿用快照。缓存限额变化时立即在本实例裁减或清空定位缓存，不写磁盘。
- Agent 本轮仅能经已有工具覆盖当前分支 N/B；用户全局设置与已有分支覆盖分别保存，不把“用户/Agent 覆盖”设计成源码中的一个共享可写对象。

例如用户只想把 State 容量改为 400、把来源定位缓存缩到 4096 项，用户文件只需：

```json
{
  "state_max_events": 400,
  "source_cache": { "max_entries": 4096 }
}
```

其他字段继承默认值；这里没有提供 N/B，因此未被分支显式覆盖时仍按模型自动计算。

### 确认后的字段与生效规则

策略分组采用 `context_budget.model_percent/parts_percent`、`window_auto`、`state_policy.token_warning_percent`、`read.lifetime_messages/default_total_chars`、`source_cache.max_entries/max_bytes`、`model_metadata_timeout_ms`。百分比使用最多两位小数，整数运算按万分比计数；规划比例必须合计 100%。自动窗口分组为 min_events/max_events/event_step/messages_per_event/tokens_per_message/evict_percent；N 在步长取整后 clamp，B 按有效 N 和移出百分比向上取整。

新增 Rule 白名单变量为 `agent_context_percent`、`state_token_warning_percent`、`read_lifetime_messages`、`read_default_total_chars`。策略非默认而模板缺少对应占位符时，报告 RULE_CONFIG_MISMATCH 并取消；默认策略兼容旧六变量模板。分支 scope 仍只接受原六个字段，不将新增策略写入 memweave.scope.v1。
