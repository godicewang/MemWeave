## 第一部分 目标和已确认决策

### 1 目标与交付边界

在当前仓库中建设一个小型实验系统，用同一批公开任务实际运行原生 Pi 和启用 MemWeave 的 Pi，保存执行证据，比较任务结果、用量、费用和时间。首版接入 Terminal-Bench 4.0 和 SWE-bench Pro V2 的适当子集，不要求运行全集。

实验系统只负责配置、执行、记录和比较。Harbor 管理 Job、Trial、并发和环境生命周期；Pi 继续管理 Agent Loop、模型、工具和原生 Session；MemWeave 继续通过正常扩展入口运行。实验代码不复制这两者的业务实现。

本次设计不包含自进化、候选生成与修复、自动晋升与回滚、共享知识库、知识审计、模型训练、独立 Agent 宿主、自建 TUI、数据库服务或分布式调度平台。不把上一轮建议的六类自建长程任务作为首版任务集，也不新增记忆协议或工具。

交付以三个能力为准：能够在冻结条件下运行公开任务，能够保留成功和失败的证据，能够从已有结果离线生成可核对的比较报告。公开任务上的成绩用于评价该子集上的任务能力；未触发记忆机制的任务不能证明长程记忆收益。

### 3 重大决策与歧义对齐准则

开发者必须主动识别影响行为、证据和验收的决定，不能以实现便利为由自行扩大范围。此准则同时适用于实验代码、配置、任务转换和结果解释；遵守根目录 [AGENTS.md](../../AGENTS.md) 的文档优先要求。

遇到以下情况，停止受影响的实现，先向用户提出集中、具体的问题：

1. 本设计、上游官方评测协议或 MemWeave 定稿规范存在冲突，或缺少无法唯一推导的必要决定。
2. 需要修改任务指令、测试、判分、补丁捕获、网络策略、时间或资源上限，或者由此改变结果含义。
3. Pi 或 Harbor 的实际公开 API 无法满足约定，拟采用内部接口、fork、patch 或绕过容量、恢复检查。
4. 需要新增公开配置参数、对外接口、持久化字段、评分口径，或改变失败、重试、取消与恢复语义。
5. 需要扩大权限、挂载 Docker socket、开放额外网络、改变认证方式、使用付费云资源或自动外传数据。
6. 本机 amd64 仿真不能可靠执行，子集因平台或数据问题显著缩减，或只能通过换版本、换环境、换任务维持执行。
7. 拟扩大到新任务集、新 Agent 类型或自进化等当前范围外功能，且尚无明确授权。

问题先用易读语言说明目的、改动范围、副作用和取舍，再给出技术细节；必须列出相关文档章节或源码位置、影响、可选方案、推荐方案和理由。未获明确答复前不执行依赖该决定的工作，可继续独立部分。用户确认后先同步直接相关设计，再编写测试和实现。

已有明确决定不重复询问。内部命名、局部函数拆分、日志排版、按已确认规则展开任务 ID 等不改变契约的细节，由开发者选择最简单、可验证的做法。不能把无回复当作同意，也不能把修复一个问题的授权扩大为改变其他模块设计的授权。

## 第二部分 实现方案

### 5 执行流程与模块

```text
实验配置与冻结产物
        ↓
静态校验 → 解析上游版本与子集 → 环境和官方控制测试
        ↓
冻结本次运行清单
        ↓
Harbor Job：原生 Pi / Pi + MemWeave
        ↓
官方评分流程
  Terminal-Bench：任务自身 verifier
  SWE-bench Pro V2：补丁捕获 → 全新沙箱重评分
        ↓
Harbor 原始结果与证据索引
        ↓
逐任务记录、对照表和离线报告
```

一个实验可关联多个 Harbor Job，例如两个被测变体，以及 Pro V2 必需的重评分 Job。首版顺序运行这些 Job；Job 内的任务并发交给 Harbor，不另建 Trial 队列或调度状态机。

| 模块 | 输入 | 输出 | 不负责 |
|---|---|---|---|
| 配置校验 | 实验 YAML、本地文件引用 | 校验结果与待解析项目 | 隐式下载、安装或推理 |
| 任务解析 | 上游精确引用、子集规则 | 来源锁、任务 ID 与内容哈希、排除理由 | 修改原任务与评分器 |
| Pi 适配 | 冻结 Pi/包、模型连接、当前任务 | 原生 Pi 执行与原始日志 | 替代 Agent Loop、改变记忆协议 |
| 执行包装 | 冻结运行清单、Harbor 配置 | Job 引用、运行退出状态 | 复制 Harbor 的并发和环境管理 |
| 结果归一 | Harbor 结果、官方评分产物 | 逐任务表、错误分类、证据引用 | 用 Agent 自述判定通过 |
| 报告 | 冻结清单与已有逐任务结果 | JSON、CSV、Markdown | 模型评审、补跑或自动决策 |

接口只服务实际调用边界。首版不增加通用 Backend 插件协议，也不预建 `submit/status/cancel` 服务层。

### 6 目录与依赖

下列为实现布局；使用说明见 `experiments/README.md`，实际通过范围见本目录 `VALIDATION.md`。

```text
docs/experiments/
└── IMPLEMENTATION_DESIGN.md

experiments/
├── README.md
├── pyproject.toml
├── uv.lock
├── configs/
│   ├── smoke.yaml
│   └── baseline.yaml
├── suites/
│   ├── terminal-bench-4.yaml
│   └── swe-bench-pro-v2.yaml
├── subsets/                      # 规则与冻结后的任务 ID，无上游题目正文
├── src/memweave_eval/
│   ├── cli.py
│   ├── spec.py
│   ├── suites.py
│   ├── runner.py
│   ├── pi_agent.py
│   └── report.py
└── tests/                        # 适配、配置、记录和报告的测试
```

Python 依赖在实验目录独立锁定；Harbor 及 Pydantic 复用其既有能力。Node 采用仓库 `.node-version` 指定版本，首个 Pi 实验目标为 1.4.0。实验层不重新承诺 Pi 兼容范围；涉及产品适配仍按原兼容规范处理。

Harbor 0.24.0 是接入候选，不能仅凭在线文档宣称它已完整满足两个任务集。编码前检查该版本实际类型和源码，核验网络策略、结果采集和官方重评分工具。等价的版本适配集中在依赖锁和实验接线；出现第 3 节所列契约变化时先讨论。

不在每个公开任务外面统一套一个自建 `pi.Dockerfile` 替换原环境。使用任务原镜像和官方环境定义，在正常 Agent setup 阶段安装固定 Node、Pi 并放入 MemWeave 产物；不得改变题目代码、依赖版本、原生工作目录或运行用户来方便安装。无法按此边界接入的任务明确阻断。

### 7 运行目录与隔离

默认实验根目录为 `~/.local/share/memweave-experiments/`，允许显式改为另一个仓库外绝对路径。其下分开保存可清理缓存和正式运行结果：

```text
<实验根目录>/
├── cache/                        # 上游任务、固定版本工具与包缓存
└── runs/<run_id>/
    ├── experiment.lock.json      # 不含密钥的本次冻结条件
    ├── run.json                  # Job 引用、停止原因及结果完整性
    ├── harbor/                   # Harbor 原生 Job/Trial 目录
    ├── evidence-index.json       # 原件相对位置、类型与哈希
    └── reports/
        ├── results.json
        ├── trials.csv
        ├── comparison.csv
        └── report.md
```

`experiment_id` 标识比较计划，`run_id` 标识一次实际执行；同一计划重跑使用新 `run_id`，不得覆盖旧目录。证据使用相对运行根目录的引用，迁移不依赖当前电脑的绝对路径。

每个 Trial 使用独立容器文件系统和真实用户主目录。Pi 配置位于该容器的 agentDir，MemWeave 继续使用该用户的 `~/.pi/memory/`，业务仓库保留任务规定的 cwd；Pro V2 的 cwd 由对应官方任务确定，不能统一搬到 `/workspace`。

只设置 `PI_CODING_AGENT_DIR` 不能隔离 MemWeave 默认记忆目录；不能在宿主上仅换 agentDir 就并行启动共用记忆的多个 Trial。不得修改宿主 `$HOME`，不得复用个人的真实 Session 或 State。

Pi 原生 Session 直接存入 Harbor 的 agent 日志归档位置，作为运行与复盘的原件。ATIF 是派生格式；不替代 Session、不用于恢复，不再建设全量聊天数据库。MemWeave 记忆数据按白名单在试验结束后采集为证据，不能把运行目录改到业务仓库。

不同任务、重复次数、变体之间均冷启动，不共享可写记忆。公开任务原有多步骤才使用其规定的会话延续；首版不自建跨任务连续会话，也不把 Harbor 的 Job 续跑当成 Pi/Task 恢复。

### 8 公开任务集与官方协议

#### 8.1 Terminal-Bench 4.0

采用官方 `terminal-bench/terminal-bench@4.0.0` 发布，解析后固定内容来源、镜像 digest 和任务哈希。官方运行入口与资源变更说明见 [TB 运行说明](https://www.tbench.ai/run) 和 [v4.0.0 发布记录](https://github.com/harbor-framework/terminal-bench/releases/tag/v4.0.0)。

本机首版只选不要求 GPU 且满足现有 CPU、内存、存储和平台条件的任务。保留入选任务官方的指令、verifier、网络和资源设置，包括其时间预算；不能为了短跑自行缩短超时、简化测试或用 CPU 替代 GPU 后仍称原协议结果。

TB 4.0 官方说明将 Agent 超时调整到 8 小时。这个上限不代表每题必然运行 8 小时；实际付费运行必须另有明确的实验费用和整体停止条件。全局止损提前停止的尝试按中断记录，不伪装成完成的官方评分。[TB 4.0 资源说明](https://www.tbench.ai/news/terminal-bench-4-0)

2026-10-27 用户确认：按官方 Dockerfile/context 原样预构建、固定平台与镜像身份，仓库外运行副本仅改镜像引用及必要的等价继承展开；保留原 verifier 模式和测试上传语义。构建或官方控制失败的候选记录于 admission.json，在模型前依既定顺序替补；具体字段、证据及验收见 [已确认接线方案](DOCKERFILE_FREEZE_PROPOSAL.md)。

#### 8.2 SWE-bench Pro V2

使用 Scale AI 官方仓库的 `v2/tasks/`、对应工具和公开镜像，固定为同一上游提交。不要使用 Harbor 的旧 `adapters/swebenchpro` 转换 V1 数据：该适配器会调整部分测试命令，且与用户选择的 V2 不同。[V2 官方任务与协议](https://github.com/scaleapi/SWE-bench_Pro-os/blob/main/v2/README.md)、[旧适配器范围](https://github.com/harbor-framework/harbor/blob/v0.24.0/adapters/swebenchpro/README.md)

按 V2 协议执行离线 Agent 阶段，只放行模型端点；保留官方 50 分钟任务预算、补丁捕获口径以及全新沙箱重评分。主结果来自冻结补丁的官方重评分，保留原运行与重评分两份结果引用；重评分不是再给 Agent 一次解题机会。Pi 适配只实现必要的启动、超时收尾和补丁交接，不改官方测试、解析器或测试清单。

2026-10-27 用户确认：上游 README 要求 verifier 不进入 Agent 沙箱，但其示例命令及现有任务默认值仍可能触发原沙箱评分。解题 Job 因此显式设置 Harbor `verifier.disable=true`，只捕获补丁；随后使用同一上游提交的 `PatchReplayAgent` 和原 verifier 在全新沙箱评分。参考解/空解控制测试不属于解题 Job，仍运行官方评分。

模型元数据请求也必须经过允许的模型端点，不能为容量核验开放通用互联网。Agent 安装和 verifier 所需网络按官方阶段策略执行，不能把 Agent 离线要求错误地扩大到全部阶段。

Pro V2 镜像采用 linux/amd64。本机先进行不调用真实模型的架构、网络、仓库与评分预检；仿真不可靠时停止相关接入并询问，不能静默切到云服务或自行重建 ARM 版镜像。HARD-51 不作为默认子集，避免把特定难题集合当作一般代表性样本。

#### 8.3 共同要求

不统一把公开任务改成独立 verifier：TB 沿用其原任务定义，Pro V2 按其本来就要求的全新沙箱重评分。不能以 Harbor 默认设置替代任务原有协议。

官方任务、隐藏测试、参考解和上游运行脚本只提供给规定阶段。不得将完整数据集 checkout、金标补丁、评测配置或后续任务指令挂入 Agent 工作区；参考解只供官方控制测试使用。

本系统只报告本地重跑的明确子集成绩，不宣称为官方认证成绩或全量榜单成绩。两个任务集分别报告，不合并成一个总成功率。

### 9 子集选择与冻结

子集选择在观察被测变体成绩之前完成，两个变体使用相同任务清单。实施时自动解析公开元数据并生成清单，无需逐题询问；需要放宽以下标准或改变版本时执行第 3 节。

1. 固定任务集版本和上游提交，列出候选任务及官方资源、平台、网络和题目分类或仓库信息。
2. 按事先声明的本机 CPU、内存、存储、架构与权限边界判断可运行性。未知条件必须补查，不能默认为满足。
3. TB 优先覆盖多个任务类别；Pro V2 优先覆盖多个仓库和语言。不使用 MemWeave 或 baseline 的成功率、token 消耗来挑题。
4. 在各分组内按 `SHA256(任务集标识 + 分隔符 + seed + 分隔符 + task_id)` 排序，再按固定分组顺序轮流取题；记录分隔符、seed、分组、顺序和最终 ID，不依赖 Python 的进程随机哈希。
5. 对所选任务执行官方参考解与空解控制测试，核验本机评分链路；控制测试不调用真实模型。失败保留脱敏诊断并阻断该任务，不修改测试来使其通过。
6. 记录所有排除或阻断理由，冻结实际计划数和任务哈希。需要替补时使用同一规则的下一候选，在变体运行前完成；变体运行后不因答错替换任务。

初始 smoke 每个任务集选择 2 题，每个变体运行 1 次，共 8 次模型 Trial；Pro 的重评分和控制测试另记，不计为额外解题尝试。首批比较建议每个任务集 12 题、每变体 1 次；规模和重复次数在实际运行配置中显式确认，不由程序自动扩大。

子集数量不足时显示实际覆盖，不补入不符合条件的任务。已冻计划中的任务运行失败仍须留在结果表中，不静默减少分母。该子集的资源筛选与规模限制必须与结果一起呈现。

### 10 Pi 与 MemWeave 接入

#### 10.1 共同启动路径

在 Harbor 已有 Pi 集成基础上实现本地薄适配，使用固定 Pi CLI 的非交互 JSON 输出。首个目标为 `@earendil-works/pi-coding-agent@1.4.0`，Node 版本读取仓库固定值。实现前再次核对目标版本实际参数与类型。

每个 Trial 显式指定 agentDir 和 Session 目录，只加载声明的实验变体。原生 Pi 变体不加载 MemWeave，也不遗留其工具或压缩设置；MemWeave 变体从归档加载正常 `src/extension/index.ts` 入口，不调用测试替身或直接注册内部业务绕过启动流程。

不把个人全局扩展、MCP、Skill、SYSTEM、APPEND 或本仓库 AGENTS 带入实验。公开任务仓库本身的上下文文件继续按 Pi 原生发现与信任机制处理；两个变体使用同样的公共接线，不静默屏蔽题目文件。

公共工具和原生提示保持一致，允许原生 Pi 正常使用文件工具保存笔记。MemWeave 的记忆工具和协议是被比较系统的组成部分，不能为使工具数相等而删去。

#### 10.2 无界面配置准备

当前生产启动器在无界面路径不弹模式框、不自动接受首次初始化，也不静默切换全局压缩。实验准备仅在该 Trial 容器内完成以下事项：

- 创建最小 Pi 配置，原生变体使用原生压缩；MemWeave 变体预置 `compaction.enabled=false`。
- MemWeave 变体从同一冻结包读取默认 Rule 资源；用户覆盖配置仅限实验明确声明的已有字段。
- 不伪造初始化完成标记，不调用交互确认的内部实现，不更改个人设置。
- 保留任务项目级设置优先级；若项目设置使 MemWeave 有效压缩开启，则报告不兼容并讨论，不能覆盖项目文件绕过。
- 在请求准备中使用现有容量核验和失败取消逻辑，不注入虚构的模型容量或测试用 verifier。

当前包带有本机检索能力。安装阶段使用包自身的资源准备函数和路径函数预热其原有 embedding 文件，并校验包内清单哈希；不在 Pro 离线阶段临时放行下载，也不缩减完整 Rule、默认提示或原生工具。预热不创建 Task、State 或搜索认知数据。

此准备不是 TUI 首次启用验收。依据分别为 [Rule 启动规范](../specs/1.1.pi_long_task_agent_rule_v1_3_final_cn_updated.md) 第 13、14 节，[启动器](../../src/extension/launcher.ts)、[初始化实现](../../src/extension/setup.ts) 和 [路径实现](../../src/storage/paths.ts)。

模型推理由 Pi 发起，Harbor 只提供执行环境和连接配置。当前 [容量核验](../../src/pi/model-capacity.ts) 对 API 类型和模型元数据有实际限制；不能因为 Harbor 能连接某个模型就宣称 MemWeave 已支持该组合。首批真实模型优先使用项目既有 DeepSeek 私有配置。

#### 10.3 超时和补丁收尾

Pro V2 任务时间到达时按官方流程停止 Agent，并从该次尝试捕获部分补丁供官方重评分；不能让进程超时直接清理容器，导致部分解丢失。正常完成也使用相同捕获口径。以外层 Harbor 超时替代这一收尾而改变评分语义时必须先讨论。

普通 Trial 的 Agent 结束、评分和证据采集由 Harbor 生命周期衔接。实现需验证管道日志采集不会掩盖 Pi 的真实退出码。第三方限轮数或观察扩展只在明确配置和共存验收后使用，不为采集指标改写请求、原始消息或临时 State。

### 11 配置与命令契约

#### 11.1 实验输入

实验 YAML 只维护必要的比较语义，由 `spec.py` 严格校验，未知字段报错；不开放任意 Harbor 参数透传、任意宿主插件加载或另一套运行时模板系统。

| 字段组 | 必需含义与约束 |
|---|---|
| 标识 | `schema_version=1`、非空 `experiment_id` |
| 任务集 | 一次运行选择一个任务集、冻结来源、子集清单；两个任务集用分别的运行配置 |
| 被测产物 | MemWeave Git commit、包归档引用及哈希；两个变体共同使用的精确 Pi/Node 版本 |
| 模型 | 提供方、模型 ID、公开 API 类型、显式思考/采样设置与私有认证引用；不保存密钥值 |
| 变体 | `pi-native` 与 `pi-memweave`；MemWeave 默认策略或已有配置的明确覆盖 |
| 执行 | Docker、实际 platform、并发上限、统计重复次数；Trial 自动重试固定为 0 |
| 协议 | 官方协议标识与资源/网络继承；不设置隐式超时或 verifier 覆盖 |
| 止损 | 明确的实验费用上限与整体时间上限；运行前必须提供合法值 |
| 位置 | 仓库外运行根目录、可访问的产物和认证引用 |

字段组的首版具体编码：`root` 为可选的仓库外绝对路径；suite 文件包括 `schema_version/id/repository/revision/tasks_dir/protocol`，只接受本设计两个官方源和完整提交；subset 文件包括 `count/seed/max_cpus/max_memory_mb/max_storage_mb`，资源字段只用于筛题，不覆盖单题资源。其余模型采样遵循 Pi 默认值，首版不提供未验证的通用参数透传。

2026-10-27 用户为首次真实冒烟明确授权：总费用最多 20 美元、整体时限 8 小时（28800 秒）。任务选择须考虑该范围，达到止损后保留部分结果并停止；不据此缩短官方单题时限或自动增加尝试。以后运行仍以其各自显式配置为准。

同日用户为本次 TB 适配后的新正式对照再次确认最多 20 美元、8 小时。新窗口从该次 run 开始，包含原始 Dockerfile 构建、官方控制、两个 Pi 变体及评分；前次窗口已结束，旧结果和费用独立保留。

以下仅说明结构；占位值和未解析引用不能通过实际运行的预检：

```yaml
experiment_id: tb4-baseline-001
suite: suites/terminal-bench-4.yaml
subset: subsets/tb4-cpu-smoke.yaml
subject:
  commit: "<完整 Git commit>"
  package: "<仓库外包归档>"
  sha256: "<归档 SHA256>"
runtime:
  harbor_version: "0.24.0"
  pi_version: "1.4.0"
  node_version: "<仓库固定 Node 版本>"
model:
  provider: "<已验证提供方>"
  id: "<精确模型 ID>"
  api: openai-completions
  auth_profile: memweave-dev
  thinking: "<目标模型已验证的设置>"
variants:
  - id: pi-native
    memweave: false
  - id: pi-memweave
    memweave: true
execution:
  environment: docker
  platform: "<已验收 platform>"
  concurrency: 2
  repetitions: 1
  automatic_trial_retries: 0
limits:
  max_cost_usd: "<运行前填写正数>"
  max_elapsed_seconds: "<运行前填写正整数>"
```

默认比较保持各产品正常上下文管理，不强行统一逐请求输入 token。模型采样、思考设置、提供方能力以及输出上限的实际差异均记入冻结记录。预算变化实验另命名配置，不能混在默认产品比较中。本期不额外实现严格相同输入上限的变体。

#### 11.2 三个命令

以下为本地 CLI 契约；实现与验收范围分别见使用说明和验收记录。

| 命令 | 行为 | 副作用 |
|---|---|---|
| `memweave-eval validate CONFIG` | 静态校验配置与已有文件，显示任务计划和仍需解析的条件 | 不下载、不安装、不启动容器、不调用模型 |
| `memweave-eval run CONFIG` | 解析与预检、冻结计划、顺序执行 Harbor Job、采集并生成报告 | 可按配置下载/构建、运行容器和调用真实模型 |
| `memweave-eval report RUN_DIR` | 从已有锁定记录和原件重建逐任务表与报告 | 无网络和模型调用；不补跑、不改原结果 |

静态校验不能把尚未下载的任务、未知镜像和模型元数据写成已核验。`run` 的模型推理阶段只能在来源、平台、官方控制测试、认证和止损条件满足后开始。

命令退出码按执行健康度区分：0 表示流程或报告完整完成，即使有任务未解出；1 表示配置、预检或程序错误；2 表示取消、止损或结果不完整。逐任务解题是否成功由结果字段判断，不能由 CLI 的 0 退出码推断。

### 12 执行顺序与停止恢复

1. 校验显式输入与冻结包哈希；包从干净提交构建，不随运行中的工作区变化。构建沿用已有脚本，不改变发布版本或 tag。
2. 解析上游精确版本，验证内容和官方工具引用，展开子集。已存在锁记录不因远程同名标签变化而静默更新。
3. 检查 Docker、架构、磁盘、官方单任务资源和网络执行能力。所需资源高于容器宿主额度时减少并发；单题仍无法满足则阻断。
4. 执行或复用条件完全相同的官方控制测试记录；变更镜像、工具或平台后重新核验。临时失败预检按根 AGENTS 要求清理临时产物，保存无凭据诊断，不冒充正式 Trial。
5. 写入不可变 `experiment.lock.json`，列出每个 `(task_id, variant_id, repetition)` 的计划；以本地运行根锁防止意外并发启动多个活动 Job。
6. 按显式顺序执行变体 Job。重复实验时交替变体先后顺序，记录实际时间，减小服务端时段差异；两者使用相同子集和模型连接条件。
7. Pro V2 对已捕获补丁执行官方重评分 Job，保持与原尝试一一关联。
8. 结束或中断时先采集允许的证据，再清理容器。采集失败写明缺失，不伪造空成功结果。报告覆盖全部计划行。

首版不自动恢复中断的 Agent 会话，也不自动调用 Harbor 的重试或续跑补齐失败行。再次执行使用新 `run_id`，显式关联此前运行；统计重复事先安排，基础设施重跑与原尝试分别保留，不采用 best-of-N。

费用止损是基于已知用量和价格快照的软限制：达到阈值后停止新任务，取消在途任务并收尾；不能保证精确硬消费上限。缺失可靠费用数据时显示未知、依靠明确整体时间限制停止，不能把缺失值记零或声称已满足费用保证。需要额外逐请求强制计费限制时先讨论实现边界。

### 13 记录与证据契约

只增加实验自己的版本化元数据，不改变 Session、State 或其他产品文件格式。首版用文件，不维护数据库、完整消息副本或独立记忆操作日志。

| 产物 | 最小内容 |
|---|---|
| `experiment.lock.json` | schema 版本、实验/运行 ID、实验代码提交、展开配置、上游/任务/评分器哈希、包哈希、精确工具版本、镜像/platform、任务与变体计划、模型设置和止损条件 |
| `run.json` | schema 版本、关联 Job 的用途与相对路径、开始/结束时间、停止原因、计划与采集数量、结果完整性 |
| `evidence-index.json` | schema 版本、逐尝试原件类型、相对位置、SHA256、是否缺失；不复制正文 |
| `results.json` / `trials.csv` | 逐任务、变体和重复编号的结果、原生评分、状态、用量、时长、错误和证据引用 |
| `comparison.csv` / `report.md` | 对齐样本、指标差值、完整性、覆盖范围、失败和结果限制 |

逐任务结果至少保存：`task_id`、`variant_id`、`repetition`、Harbor Job/Trial 引用、`execution_status`、`native_reward`、`success`、`score_source`、`usage`、阶段时间、`error_type`、证据引用。`native_reward` 保留官方数值或对象；没有有效判分时 `success=null`，不能擅设通用阈值。

Pro V2 的 `score_source` 指向官方重评分，并关联 `model.patch` 哈希及其原运行；原运行得分仅作诊断。补丁不可修改后继续冒用原尝试身份。

冻结与原件写入采用原子提交，已有运行不得被覆盖；派生报告可重新生成。中断后仅凭目录存在不能认定实验完成，必须校验计划行、评分原件与哈希。路径解析拒绝越出运行根目录，归档不跟随指向凭据或其他目录的符号链接。

主证据包括 Harbor 原始结果、Pi 原生 Session、模型用量、评分器输出、Pro 补丁与重评分、允许采集的 MemWeave 记忆文件。临时请求视图、预算和提醒不能写回 Session；首版不为补充统计改动生产 hook。现有原件无法可靠提供的观测字段标为缺失。

### 14 指标和比较方法

首版主要指标是各任务集官方成功判据下的任务成功率。Pro 必须满足其官方测试判据；不通过 CLI 成功、Agent 回答或自报测试结果代替官方判分。

| 指标 | 口径 |
|---|---|
| 计划完成情况 | 计划、实际开始、有效判分、失败、中断、未运行、缺失数量全部列出 |
| 运行成功覆盖率 | 有效成功尝试数 / 原计划尝试数；只作运行视角，不能冒充官方 resolved rate |
| 有效样本成绩 | 按官方判据统计，同时公布无效、基础设施失败和中断的数量及原因 |
| 成对结果 | 同任务、同重复编号比较两变体，列出双方成功、仅一方成功、双方失败与缺失配对 |
| 用量 | 原始供应商/原生 usage，区分输入、输出、缓存；压缩与相关额外推理不能漏计 |
| 费用 | 使用可核对价格快照估算，记录币种、时间和来源；未知不记零 |
| 时间 | 安装/环境准备、Agent 执行、评分/重评分、总墙钟分别记录 |
| 稳定性 | 任务失败、基础设施错误、评分错误和取消分别统计 |
| 记忆诊断 | 原件可得的记忆工具调用、Task/State 情况；原生 Pi 对应项为不适用 |

同一对照保持任务、模型提供方/ID、采样和思考设置、公共工具、公开任务协议、平台和计划重复数一致。MemWeave 正常上下文策略与原生压缩不同，报告如实描述；不能据此宣称只是单个内部算法的纯消融。

用量按目标 Pi 与供应商已核验的字段语义归一，保留来源。不能把缓存 token 或 reasoning token 与包含它们的总数重复相加；未知用量保持 null。

子集报告首先列原始分子分母和成对差值。重复运行不是新题目；需要区间估计时按任务聚类计算，保留分组与方法。小样本不以一次胜出宣称统计优势，也不跨任务集平均成绩或拿本机仿真耗时外推原生 Linux 性能。

没有记忆调用或窗口管理不自动扣任务分；这些诊断不能取代最终产物质量。未触发窗口、回读或 State 压力时，明确该实验不能验证对应记忆机制的效果。

### 15 失败分类与资源边界

下列是结果归一标签，不是另一套 Trial 执行状态机；原始 Harbor 状态与错误必须一并保留。

| 情况 | 记录方式 |
|---|---|
| 已完成官方判分 | `scored`，保留通过或未通过结果 |
| Agent 崩溃或达到任务预算 | `agent_error`；若官方协议仍能对部分产物评分，另保留有效评分，不抹去错误 |
| 容器、镜像、供应商网络等外部故障 | `infrastructure_error`，不擅自改成 Agent 能力失败 |
| 评分器失败或输出不能解析 | `verifier_error`，没有有效评分时 success 为 null |
| 用户取消或整体止损 | `cancelled`，保留已发生的用量和停止阶段 |
| 计划中尚未启动 | `not_run`，保留在原计划分母和清单中 |
| 原件缺失、哈希不符或关联不明 | `invalid_result`，不能进入完整成对比较 |

网络策略必须实际生效，不能只记录一个配置值；尤其 Pro V2 要验证模型端点可达、通用外网被阻止，以及评分阶段仍符合原协议。公开协议或框架做不到时先报告，不默认放宽。

Harbor 与其宿主侧适配器属于受信任控制程序，题目和 Agent 不能修改它们。不给被测容器宿主 Docker socket、个人 home、SSH agent 或整份私有 Pi 配置目录。需要这些权限的题目不进入当前默认子集。

认证复用仓库外 `~/.local/share/memweave-dev/pi-agent/` 私有配置，只提供推理需要的最小凭据文件；不将密钥放入 YAML、命令参数、报告、镜像层或 Git。采集采用白名单并排除 auth。若日志意外包含凭据，停止相关归档并报告处置，不就地修改原 Session 掩盖问题。

正式实验失败证据按上述结果目录保存，不自动删掉旧运行；缓存可显式清理，不能连带删除实验原件。临时可行性验证失败后的清理仍遵守根 AGENTS 的专门规定。

### 16 开发切片和验收

每个切片先写边界测试，再实现最小闭环；不同时建设无调用方的扩展层。代码任务开始前再次检查工作区与相关定稿规范。

| 切片 | 实现范围 | 退出条件 |
|---|---|---|
| 一 | 配置、路径与任务锁定，两个公开任务集各选最小 CPU 子集 | 来源和哈希固定；静态校验不产生执行副作用；官方控制测试与 amd64 预检可核对 |
| 二 | 固定 Pi、两个变体、Harbor 执行与 Pro 官方重评分 | 一个任务在两变体上完成全流程；无相互污染、无凭据归档，部分补丁和失败可保留 |
| 三 | 批量运行、结果归一和离线报告 | 两个任务集各有独立报告；计划行完整、成对比较准确、取消和缺失不被隐去 |

最低验收矩阵：

| 层次 | 必验内容 |
|---|---|
| 纯单元 | 非法/未知配置、占位值、路径越界、任务去重、确定性子集、版本/哈希不匹配、缺失用量与评分、比较分母 |
| 本地替身 | Harbor 成功/失败/取消/部分输出、退出码保留、Job 关联、报告幂等重建；不冒充真实 Harbor 或模型 |
| 真实 Harbor 与 Docker | 官方镜像、参考解/空解、网络、资源、日志收集、进程退出、架构与文件边界；不需要真实模型 |
| 真实 Pi 与冻结包 | 正常入口加载、原生模式无记忆工具、MemWeave 有效设置、独立 Session/记忆、容量失败取消；与供应商调用分别报告 |
| Pro V2 专项 | 同一次运行补丁捕获、50 分钟超时收尾、官方全新沙箱重评分关联、未改测试与脚本 |
| 小额真实模型 | 项目既有 DeepSeek、两个变体、两个公开任务集 smoke；明确实际调用数、用量和费用，不自动放大规模 |
| 产品边界 | 实验不改原始消息、不把临时提示持久化；不注入开发文档；实验代码与依赖不进入 npm 发布包 |

官方任务与评分脚本执行证据必须与 Mock 测试分开。设计完成、类型通过、入口能启动均不等于公开评测已经跑通。文档修改本身不启动这些运行测试。

涉及产品源码时执行既有相关单测、类型和集成检查；正式发布仍按 [发布流程](../../发布.md) 与 [发布测试](../../发布测试/README.md)，本实验不增加发布授权。模块完成后依根 AGENTS 形成清晰 commit，并按重要检查点核对后推送，不夹带用户无关工作。

### 17 后续扩展的最小准备

仅保留版本化配置与结果、冻结包输入、相对证据引用，以及集中在少数文件中的 Harbor 接线。以后其他程序可以生成同样配置、提供同样格式的包并读取结果，不要求先建设服务或数据库。

增加新的公开任务集时复用这些边界，先确认协议和验收；增加其他公开 Agent 时先确认比较目标、模型与认证边界。未来 MemWeave_RSI 的候选、知识和晋升逻辑不放入本目录，本期不定义这些接口、对象或工作流。
