2026-10-28，按 [已确认设计](RUNTIME_CACHE_DESIGN.md) 完成实验接线。实现源码为 `005e5ce`，机器可读结果含逐文件源码哈希、镜像 ID、软件身份和逐次测量，见 [JSON](results/runtime-cache-20261028.json)。产品源码、官方题目与评分协议没有改动。

## 实际通过范围

68 项实验自动检查、Ruff 和 Python 源码编译通过。覆盖缓存身份、候选变化不影响原生软件对象、模型资源/路径变化失效、内容篡改、未完成提交、归档越界/链接/重复成员、并发读取、无凭据准备、正式 Trial 禁止创建对象、冻结摘要检查、准备失败阻断和旧报告兼容。这些检查不冒充真实供应商或公开题目成绩。

真实验证使用 Harbor 0.24.0、Node 24.22.0、Pi 1.4.0，以及原实验冻结的 MemWeave 包 `4d089821…ab7c04`。在本机 linux/amd64 仿真中，对以下三个原始官方镜像各运行原生/插件两个变体，两轮均使用全新容器，共 12 次无模型加载验收：

- TB 4.0：Roy、Production Planning，覆盖 Ubuntu 22.04 与 Debian bookworm。
- SWE-bench Pro V2：Element Web 的原始官方镜像。

两变体均使用实际 Pi SDK 的默认工具/系统提示，插件变体加载完整生产扩展入口。插件实际计算 384 维 embedding，原生没有记忆工具，插件注册 12 个记忆工具，有效自动压缩分别为开启/关闭。12 个 Session ID 全部不同；预检不调用 `prompt`，不发送用户解题消息、不执行 verifier，不产生能力评分。源码与镜像身份在两轮前后保持一致，原件索引哈希复核通过。

另外在 Roy 的两个新容器上启动真实 `pi --mode rpc` CLI，发送 `get_state`、`get_commands`，未发送 `prompt`；预检使用 `PI_OFFLINE=1` 禁用模型目录联网刷新，不提供认证。双方成功返回，消息数均为 0；插件拥有 `memweave-setup`/`memweave-restart` 命令，原生没有。检查后写入题目目录、Pi profile 与记忆目录哨兵，再销毁容器；下一个实例在安装前确认均不存在。两个 CLI Session ID 也独立。缓存只复制软件归档，不从这些容器采集更新。

三个镜像、两个变体的整轮软件准备和加载预检墙钟，从 **862.95 秒（14分23秒）降至135.69秒（2分16秒）**，约减少84.3%。该时间包含预检 Job 的容器启动/收尾与实际 SDK/embedding 加载；不包含此前的官方镜像构建/控制，也不包含模型解题。每任务/变体每轮只测一次，不能外推所有硬件、任务或运行次数。

正式运行报告另列 `software_preflight_job_seconds`、`solve_job_seconds` 和 `overall_wall_seconds`。Pro 的重评分仍是独立 Job，其原生评分时间保留在逐题记录中，也进入整体墙钟。不能把软件准备收益解释为模型解题加速或费用下降。

## 证据、清理与限制

完整无凭据原件位于仓库外默认实验根的 `analysis/runtime-cache-final-20261028T092439Z/`。`cold/`、`warm/` 包含原生 Harbor 结果、软件计划/对象锁与证据索引；`cli/` 和 `cli-summary.json` 为真实 CLI 检查。最初的 SDK 导出探针失败发生在模型调用前，已修正为公共 `ModelRuntime` 接口；临时失败目录、容器及三个被替代的软件对象已删除，最终验证对象保留。验收结束后 Docker 无活动实验容器。

本轮没有读取/注入真实 API 密钥，没有模型推理或新增付费实验。加载检查不能替代真实供应商请求、Rule 请求前渲染、模型容量核验、完整业务解题和官方判分。旧 TB/Pro 成绩保持原记录；不据此声称业务 bad case 已修复。未做新的 ARM/GPU/远程宿主验收，也没有发布 npm。
