# Kubernetes原题业务结果接线

LONG-04继续使用已冻结的SWE-Marathon源题、原始验证器及受保护集成测试，不以源代码保全或CTRF外观代替业务正确。新增评估侧附件读取原始`metrics.json`、reward、保护集成二进制清单及完整cargo输出；按哈希冻结的原题parser离线重放，再交叉核验计数、结构、分母和奖励。它附加于已有过程保全gold，不改变产品接口、actor上下文、原验证器或评分权重。

本切面的原清单有106个二进制区段、1407个受保护测试；重复同名区段按原parser的多重集合和每区段上限处理，不能按字符串去重。Agent自编单元测试及doc测试均不计入。原始partial分母是`max(受保护passed+failed, 原保护阈值)`，不把原始单元测试数加进去；原二元奖励还要求完整区段结构且零受保护失败。partial等于1本身不证明二元通过。

明确结束的构建拒绝与未执行测试分别记录：已完成原验证器的build_failed可确认为交付失败，不能声称逐项测试都执行失败。只有initialized、被取消或缺cargo原件时仍需补证，不能借原始默认reward0冒充完整验收。正、负、缺字段及原件不一致分别测试；免费参考／空解控制只证明评估器和环境，不是模型成绩。

源清单来自独立参考控制开始时由原验证器恢复的受保护清单，冻结在evaluator-only目录，不挂载到被测actor。正式准入仍须通过资源、完整Pi采集及供应商canary，不能仅凭该组件存在宣称题目已准入。
