# local_baseline 实现设计

状态：评分口径与本轮运行预算待用户对齐；尚未实现、未运行模型。

## 第一部分：目标、范围和待确认取舍

本套件在实验系统中加入 `local_baseline`，与 SWE-bench Pro、Terminal-Bench 分开报告。当前源码/归档是待测基线；任务是测出和保存实际水平，不修改产品提示或修复疑难 case 来提高这次成绩。

分为两部分：

1. **功能正确性回归**：复用根目录 `发布.md`、`发布测试/run.mjs --full` 及发布矩阵，保留资源、类型、单元、实际宿主、产物、分发和真实模型检查。既有 Mock/本地 HTTP 控制明确标注，不冒充供应商运行；原生 Pi 不适用的插件专属发布检查记 N/A。原有门禁不被能力分数或平均通过率取代，仍不自动授权发布。
2. **badcase 能力评测**：覆盖 `docs/DIFFICULT_CASES.md` 的 MW-001—MW-011，使用同一模型的真正 Pi CLI 与加载冻结生产包的 Pi CLI，完整默认提示、原生工具、完整 Rule。每个有效执行的 case 给出 0—100 分、逐项得分依据和证据引用；保存失败，不重采成通过。

待确认的首要取舍：原生 Pi 没有 Task/State 工具，不能因不存在这些接口而在共同能力分中直接扣分。推荐每例的 100 分衡量两边可共同完成的业务、恢复与依据质量，插件专属协议检查另列通过/失败/不适用的诊断。另一种方案是另外再给 MemWeave 一张机制遵循的 100 分表，原生该列 N/A，两类分数不混合。

稳定性的承诺是测试输入、评分规则、程序兼容与同一原件的重复判分稳定；真实模型表现仍可能波动。本次每变体完整运行一次，只构成首个基线样本，不宣称统计稳定或普遍优势。

新增套件、评分语义和预算按根 `AGENTS.md` 第 2 节及实验设计第 3 节先对齐。两项决定确认后，先定稿本文件与相关实验契约，再实现。TB 的镜像提案是另一项未决问题，本任务不视为已批准它。

## 第二部分：测试与实现边界

### case 覆盖草案

下表给出每个 case 必须覆盖的行为。各项权重、输入、预期输出和诊断字段在模型运行前冻结，不能依据观察到的两个变体成绩调整。

| case | 场景与必须验证的内容 | 插件专属诊断 |
|---|---|---|
| MW-001 | 成功、受阻、无新认知三种维护任务；exit=0 但 passed=false；只执行允许的探针；恢复时准确说出阻塞与未验收状态；在延迟补记间隙另设恢复检查 | Task/Goal、写入尝试与成功阶段、Fact/Decision 和证据；不强制每轮写 State |
| MW-002 | 原生 schema 拒绝与业务校验拒绝分别覆盖；业务接口错误后修正，保留必填字段和原约束；记录恢复轮数与重复外部动作 | State 参数/来源严格拒绝、非法输入不落库；与两边共同业务纠错分开 |
| MW-003 | 仅 Recent、仅 State、两者并存分别核验；真实长程交互跨过默认窗口边界；不能误删持久信息，原始 Session 保留 | Window/State 批次各自提交、工具误用、未准备批次拒绝；结构压力与业务能力分开 |
| MW-004 | 冻结包、独立进程恢复、原文前缀核对、新增审批约束；旧要求保持、新要求恢复后可用，不能仅凭版本增加判为记住 | memory_read/state_append 实际轨迹、最终 scope、新 Fact 内容与来源 |
| MW-005 | 有多个相近历史项目/任务，选择正确工作并避免误恢复、重复创建；加入需要澄清的候选 | 搜索先后顺序、候选与最终绑定；原生接口不存在不计共同能力失分 |
| MW-006 | 整体目标包含多个阶段与最终验收；先交付小阶段，再按整体目标发现和继续；保留后续目标而非只记第一步 | 首次 Goal 的整体覆盖、关键词/摘要、后续检索/恢复；非空/长度合格不等于覆盖正确 |
| MW-007 | 全局规则变更和逐批明细混合；变更退出近期历史后正确应用适用范围，历史快照保持原口径 | 认知粒度、来源、后续恢复；不以 Fact 越少越好评分 |
| MW-008 | 撤回未发生/明确发生、只读配置/真正执行探针、未知状态；分别判字段值与依据 | 真实工具轨迹能否支持“已实测”等表述，不能只做关键词字符串比较 |
| MW-009 | 有依赖的初始化与业务动作，成功/失败/恢复已有任务；被拒动作不得产生副作用，恢复后恰好执行一次 | 绑定结果先后、同批依赖拒绝、重试次数与真实副作用 |
| MW-010 | 明确区分程序化计算与逐项语义审阅；原始材料植入语义例外；检查处理正确性和可见原文覆盖 | 只核对真实模型可见的工具结果，不把 readFile 调用等同逐项审阅；不强塞无关重复文本 |
| MW-011 | Agent 编写审计业务代码；混合格式/业务错误的全局时间顺序，以及 MAX_SAFE_INTEGER×10000bps 的独立整数参考 | 与产品记忆实现无关；公开示例、冻结隐藏用例、补充边界分别列出，不复用旧浮点 oracle |

### 执行原则

- 能力阶段通过固定 Pi 的 `--mode rpc`/原生 Session 完成多轮工作与进程恢复，不直接调用模型 SDK/API 替代 Pi，不复制 Agent Loop。
- 不伪造 assistant/tool 历史来假装真实长程运行，不以缩小 Window 代替默认窗口基线。结构性回归 fixture 与真实交互证据分别列出。
- 任务工作区、Pi 配置、记忆、Session 和认证隔离；产品从冻结归档加载正常入口。两变体使用相同业务输入、模型与思考设置，允许原生 Pi 正常保存业务笔记。
- 评分程序与隐藏预期在受信任执行侧，任务只能看要求和公开材料。业务产物按已声明语义核验，不要求模型最终聊天回答套一个脆弱 JSON 包装。
- 评分前检查执行健康度与证据完整性。格式适配、RPC 版本、解析或环境故障标记 invalid/infrastructure，不伪装成模型 0 分；有效的错误业务产物按冻结标准扣分。
- 每个评分器必须通过 gold=100、空/错误产物、等价表达、针对性植入缺陷和同一原件至少三次一致性检查；数值参考使用独立整数推导。评分器故障修复不得改动已发生原件，重评版本和原因必须记录。
- 发布回归与能力结果各自保存；发布入口中断/失败仍保留原结果，能力评测可作为独立实验继续，不能据此宣称发布验收通过。
- 原计划所有 case 保留在报告，显示覆盖率、错误和未知值。总体能力分不混入功能回归门禁，也不与公开 benchmark 成绩平均。

### 接入范围

拟在 `experiments/` 下增加本地 suite 配置、case 输入/说明、评分器自检、真正 Pi 多轮执行适配及发布回归包装，继续复用现有 `validate/run/report`、冻结清单、预算、凭据防泄漏和原件索引。扩展范围限于该套件，不预建通用工作流或自进化接口。

交付包括：定稿规范、每例可核对的 100 分 rubric、可执行验证程序、评分器自检结果、两变体各一次完整运行、逐例对照表、发布功能回归状态及可离线重建的结果。未执行/受阻项明确保留，不能用已有历史报告冒充本轮数据。
