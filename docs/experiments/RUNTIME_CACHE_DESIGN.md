# 实验软件缓存与独立试验环境

日期：2026-10-28。状态：用户已确认复用准备成果、隔离每次解题状态；本文件限定本次实现范围。

## 第一部分：目的、范围和取舍

此前 TB 的三次插件尝试在安装阶段失败，尚未调用模型；每个 Trial 重复下载与安装也放大了总墙钟。现在把固定软件准备移到模型运行之前，准备成功后保存干净的软件归档，每次试验复制到新的官方任务容器。

官方 Dockerfile、镜像、题目、测试、网络与单题预算保持既有协议。不会把解过题的容器当模板，不保存数据库、后台进程、仓库修改、认证、Session、Task、State 或搜索索引。不同变体和重复仍有独立可写实例；同一题的一次连续解题沿用同一容器。

Node、Pi 与插件依赖含平台相关二进制。Node 下载按版本/架构复用；安装完成的软件按官方镜像 ID、平台、Node/Pi 版本和准备代码哈希缓存，插件再绑定候选包哈希。这样保守地避免跨系统 ABI 混用。embedding 文件按包内资源清单哈希复用，实际路径与校验仍调用产品函数。首次遇到新镜像仍需准备一次；这比自建统一 Agent 镜像简单，也保留原始任务环境。

所有入选任务的两个变体在首次推理前完成无凭据、无模型预检。准备失败阻断整个实验，不能当作答错，也不触发任务候补。缓存损坏明确报错；显式清理对应缓存后才能重建，不在已冻结的模型运行中隐式重装。此改造不授权新的付费重跑。

## 第二部分：实现与验收

### 1 资源和目录

`<实验根>/cache/agent-assets/v1/` 保存：

- `downloads/`：固定 Node 官方归档、官方 HTTPS SHASUMS 来源和 SHA256；缓存命中也检查内容。
- `<key>/manifest.json` 与 `payload.tar`：Node+Pi、插件包及依赖、embedding 三种独立对象。发布采用锁、临时目录与原子重命名，未完成目录不是缓存命中；归档检查路径、链接边界和摘要。
- 不缓存用户配置。缓存内容仅来自无凭据准备容器；不从正式 Trial 反向更新。原生 Pi 不接收插件包、模型文件或记忆目录。

`runs/<run_id>/runtime-assets.json` 是本次不可变缓存计划，记录镜像映射、软件身份和对象键；对应 SHA256 写入内部 Harbor Agent 参数。`runtime-assets.lock.json` 在预检完成后冻结各对象 manifest/payload 哈希与预检原件引用，纳入 `experiment.lock.json` 和证据索引。缓存是可清理资源，不是历史成绩的必需原件；离线报告只依赖本次保存的清单和日志。

### 2 准备与部署

继续使用 Harbor 0.24.0 的正常环境和 Installed Pi 接口，不 patch Harbor/Pi。增加内部准备模式；它仅运行固定安装命令和公开 SDK 加载检查，不调用 `prompt`、模型、题目解答或 verifier。准备 Job 明确标记用途，不计入成绩、模型尝试或成功率。

准备顺序是官方任务准入/控制 → 全部原生和插件资源准备与加载检查 → 冻结软件对象 → 正式变体 Job。准备 Job 的安装时限来自本次整体剩余时间（单次最多一小时），不使用正式 Trial 的 360 秒安装上限，也不改官方解题时限。全局费用与时间监控覆盖准备阶段；没有新增公开 YAML 字段或 CLI 命令。

安装固定 Node 使用官方精确版本二进制与校验和，消除 NVM 先查询浮动 major 的步骤。缓存部署后通过显式 PATH 启动同一 Pi CLI；薄适配仅移除 Harbor 固定的 NVM 引导前缀，不改其提示、工具、模型参数、Session 或输出采集管道。

每次正式 Trial 只校验并复制固定归档到真实用户 home，写入该实例的最小配置和私有认证。插件 Rule 从冻结包复制；embedding 通过产品 `memoryPaths`/`ensureEmbeddingModel` 校验。不能伪造初始化标记，不能覆盖项目设置。安装后核验 Node/Pi 版本；预检还通过公开 SDK 加载完整生产入口、默认工具和系统提示，检查插件工具、有效压缩设置与本机 embedding 原生依赖。预检与正式解题使用不同新容器，不把预检产物当作初始记忆。

### 3 证据与失败

每个 Trial 的 `experiment-setup.json` 记录对象键/摘要、缓存命中或创建、部署耗时、版本和 cwd。准备 Job 原生阶段时间单列；正式 Trial 的安装时间表示复制与独立配置时间。报告另列准备墙钟、正式 Job 墙钟、整体墙钟，不能把缓存首次构建时间算作模型解题收益，也不能把前后不同实验的墙钟直接解释成能力提升。

每次正式 Job 前后验证冻结镜像、任务、实现及缓存摘要。缺失/损坏不能降级为网络重装或继续运行。旧运行没有缓存字段时仍能离线报告，显示不适用。

### 4 验收

先做自动边界测试：键隔离、归档路径/链接、篡改/不完整缓存、锁与失败提交、原生/插件分离、无凭据准备、预检失败阻断、正式阶段禁止缓存创建、保留 Pi CLI 和官方预算、旧报告兼容。再用真实 Harbor/Docker 与现有官方任务镜像做无模型验证，记录首次准备和再次部署时间、完整插件加载、本机 embedding 运算及不同容器配置/记忆隔离。真实供应商推理须另行取得新费用/时限授权。
