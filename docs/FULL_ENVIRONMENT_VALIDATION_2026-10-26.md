### 全套 4 项失败

| 场景 | 发生的事 | 能得出的结论 |
|---|---|---|
| 组件成功交付 | 设置和业务验证完成，但没有形成预期的重要 F/D，State 只有 Goal | 保存重要认知仍不稳定；精确目标夹具修复并没有顺带解决漏记 |
| 组件验证被阻塞 | 未保存断言要求的失败/未完成边界认知 | 业务答复和可恢复 State 是两项独立验收；诊断复测保存成功不能掩盖这次失败 |
| 26000 条合成历史后的重开 | 命令准备、种子及 reload 之后，模型没有通过工具建立预期的新 Task，当前绑定仍为 null | 原生命令不推理的边界正常；接下来依赖模型调用 task_create 的步骤不够稳定 |
| 跨 Task 盲读图片 | 图片已进入最后请求，但回答把 left 写成字符串 `circle red`，而非要求的 shape/color 对象 | 这一次是输出结构失败，不能描述成图片没传到模型 |

7 项诊断中的另一轮图片失败有所不同：模型调用两次 `memory_read`，最终出站没有图片，回答包含 `CROSS_TASK_R_NOT_ALLOWED`。现有代码中，此错误对应将 R 引用与其他 Task 的 task_id 混用；R 是当前 Task 注册的引用。该轮通用轨迹没有保存参数，不能仅凭回答断言实际参数。随后三个固定、额外记录参数的样本均正确先跨 Task 读 U 引用，再在当前 Task 读取 R2，不带旧 task_id，三次均收到图片；其中一次 OCR 错一位。**引用使用、图像送达、识别和结构化回答是不同验收层，不能归为一个已定位的传输 bug。** 本轮不修改这些产品行为。

## `state_append` 的推荐优化：待确认，未实施

### 第一部分：目的、范围、代价和选择

建议先做一件小事：**让已有的保存时机出现在模型选工具的位置，使用 Pi 原生工具摘要，并前置现有工具描述中的使用时机。** 保留模型自己判断重要性、保存证据和不重复写入的规则，不增加阶段状态机或额外反思请求。

目前 `state_append` 已在 API 工具清单里，工具也能正常执行。问题并非工具没有注册。但是我们没有提供 `promptSnippet`，Pi 因而不在默认 System 的 Available tools 摘要中列出它；现有长描述先讲参数约束和示例，交付前保存的时机位于后半段。模型围绕业务修复及其验收结束回答时，可能没有将记忆保存选为下一步。这是已经核实的展示缺口和合理的影响假设，**尚未证明是漏记的唯一根因，也不承诺补齐后不再漏记。**

修改可局限于工具注册元数据：把原有“什么时候该用”前移，以一行 `promptSnippet` 接入 Pi 的摘要，精简重复描述；正文限制、参数校验、证据语义及完整 Rule 均保留。相比再给每轮末尾增加常驻检查，位置更贴近工具选择，改动更小。代价是原生 System 多一条工具摘要，需要实际计量净 token 变化；不能承诺提示零增长。

这不需要为每次交付追加一轮审计模型调用。不过，一次本来漏记的交付若正确补上 state_append，会使用现有工具循环，可能多出一次工具后的原生请求；可以批量保存少量必要认知，避免拆成多次写入。普通问答和没有重要新增时仍不写。这里不增加程序对“阶段结束”的自动裁决，仍以现有交付、受阻、改方向或暂停等语义由模型判断。

### 第二部分：接线和验证办法

1. 本机精确 Pi 1.3.0/1.4.0 的公开 `ToolDefinition` 均支持 `promptSnippet`；默认 System 构造只把提供 snippet 的工具加入摘要。拟为 state_append 提供一句用途，例如：“保存交付前尚未写入 State、对任务续接必要的重要新事实或决定；已有认知和普通问答不重复写。”
2. 将现有 description 中的保存时机移到开头，再说明 items/type/content/evidence、长度和示例，删除相应重复语句。工具名、schema、返回、运行逻辑和持久化不变。不引入新参数或通用指导框架。
3. 用户自定义 SYSTEM 时，Pi 可以不生成原生工具摘要；因此不能删掉 Rule 和工具 description 的现有核心约束，不能以 snippet 作为唯一依赖。保留用户的 System 优先级和兼容边界。
4. 实施前先对齐这项模型可见元数据变更，并更新直接相关设计。实施后使用同一完整环境、同一组件目标、固定样本数比较修改前后：成功交付、失败阻塞、没有新认知的后续追问、短问答。检查有证据的重要记忆覆盖、是否虚构或重复、业务目标完成、真实请求数及 token。**不能只看调用率，也不能为了绿色添加“必须调用 state_append”的测试提示。**
5. 每组样本全部记录后再判断；若收益不足，撤销该小改动或继续报告。暂不同时调整采样、Rule 尾部、自动写入或引入额外 Agent，避免无法判断哪个因素有效。

本轮没有实施上述建议，也没有把它作为失败已经解决的理由。
