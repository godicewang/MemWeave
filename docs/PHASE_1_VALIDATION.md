## 实现与接口边界

| 模块 | 已完成范围 |
|---|---|
| `src/config/schema.ts`、`read.ts` | 六字段 schema、200/40 和 2000/100/200/20 默认值、UTF-8/JSON/数值/N/B 校验、全局默认与实例覆盖合并、不可变快照 |
| `src/storage/paths.ts` | 集中提供 `~/.pi/memory/`、config 和 Rule 路径；测试只覆盖到系统临时目录 |
| `src/rule/` | 每请求读模板、六变量单次白名单替换、模板文本/哈希、原生有效 system 自有标记内插入/替换；不改 Session |
| `src/pi/model-capacity.ts` | 通过公开认证接口核验实际模型容量，派生 `floor(C_model / 2)`；缺失/不唯一/失败取消，不改宿主目录 |
| `src/pi/system.ts`、`rule-services.ts` | 复用 Pi 有效 system 重放；同一配置/容量快照传至 Rule 与后续模块接口；无跨请求可变 frame |
| `src/extension/index.ts` | 接入正式模块，沿用阶段 0 的版本/压缩检查及先 abort 后诊断 |

配置与模板只读，不自动初始化，不回写新默认值。全局配置要求显式填写六个字段，未知字段拒绝；部分实例覆盖仅是内部接口，未决定或写入新的 Session/分支持久化格式。Pi 的 `settings.json` 与 MemWeave 配置仍是两种独立配置。

容量适配当前对 `openai-completions` API 使用所选模型的认证/端点，读取 `/models` 中唯一匹配模型的精确 `context_window`。每次逻辑请求核验一次，无容量缓存或持久化文件；15 秒超时，认证/响应正文不进入诊断，重定向拒绝。其余 API 或缺少该精确字段的供应商明确诊断，不猜展示单位、不回退目录。这个内部适配没有包装或替代 Pi 的推理请求。

### 纯函数与资源

六个默认值及合法显式覆盖保留；缺失/额外字段、非对象、非正安全整数、B>N 均报错。未知/缺失变量、非法表达式、未闭合/嵌套占位符、无效 UTF-8、空模板、损坏/越界/重复 Rule 标记均拒绝。模板只处理自有文本，用户提示中的 `{{...}}` 原样保留。

两份规范 Rule 正文逐字相同，允许末尾换行差异；发布资源与独立模板一致。原生增量 system 与工具声明使用 Pi 的重放函数，测试覆盖工具删除、工具调用/结果配对、参数、推理签名及图片结构保留，输入对象不被修改。

### Pi 与本机 HTTP

正式模块覆盖首次请求、工具续跑、热改配置与模板、reload、项目 SYSTEM/APPEND/AGENTS 信任、共享文件下独立实例覆盖。另通过 Pi 原生扩展加载器实际执行正式 schema、system 重放和热读取，覆盖直接 Node 导入不能证明的加载兼容性。每请求仅一份 Rule；临时 Rule 和测试 State 不写 Session，原生提示文件保持原文。

真实 Pi 供应商适配器连接本机 HTTP 服务：配置/模板非法时新增推理 POST 为零；元数据缺失、重复冲突或 HTTP 错误也不发推理 POST。元数据认证通过 Pi 公开接口解析，错误响应中的测试秘密未进入诊断。读取元数据的 GET 与推理 POST 分开计数，不将“推理未发送”误写成“没有任何 HTTP”。

供应商内部 HTTP 503 重试复用同一请求消息、配置和容量快照，即使磁盘文件与元数据已改变也不重读；下一逻辑请求才使用新值。模型切换更新容量快照，奇数容量向下取整；没有修改 Pi 全局模型目录。
