# Vibe Coding 实现规划

## 总原则

不要一次性让 Codex 生成完整系统。按阶段交付可运行的垂直切片；每个阶段必须有测试、可恢复的数据行为和明确验收。开始任务前先读 `AGENTS.md` 与 `docs/INDEX.md` 指定的规范。规范冲突或缺少决定时，停止并询问用户。

## 阶段 0：SDK 宿主与 Pi 适配接入

不实现业务功能，先确认技术入口：
- 在当前唯一仓库建立 TypeScript strict 与构建配置；锁定 Pi v1.3.0 SDK 和一致的依赖树，不依赖全局 `pi`。
- 建立薄 `memweave` 入口、`src/pi/` 宿主工厂和内部扩展工厂，复用原生 Session/循环/工具；验证 `prepareRequest`、`context` 和发送检查的实际调用时序，不另写 Agent Loop。
- 注入每实例 SettingsManager 适配，验证只关闭本 Runtime 的 auto-compaction：阈值、overflow/length 恢复均不自动产生压缩或恢复用 `context_edit`；手动压缩取消，用户共享设置与普通 Pi 实例不受影响。
- 验证 reload、无关设置保存、项目 `enabled: true` 和启用压缩命令不能绕过实例约束；启用被拒绝时提供明确诊断，不假装设置成功。
- 验证 `rule.md` 请求前读取/渲染后，下一次请求可见新参数；原生 SYSTEM/APPEND 不丢失、不重复。
- 接通原生 `InteractiveMode` 与 Runtime 生命周期；初次启动、新建/切换/恢复 Session、分支、reload 后都经过相同工厂和幂等重绑，退出正确释放订阅与资源。
- 保留实际 `agentDir`、凭据/资源发现及项目信任；按原生配置接入 MCP、codemode、tool_search 等工厂，不把 SDK 最小默认能力误认为完整 CLI。
- 记录真实 API 类型、入口代码和可复现的 smoke test。

**验收：** 最小 MemWeave 宿主可运行原生循环与内部扩展；请求链、失败阻断和双实例隔离有测试；不为接入改写用户规则/压缩配置或 Pi 核心。原生恢复/更新提示不能让用户绕开 MemWeave 入口。具体公开函数组合可随核对调整，业务语义与原生协议必须保持。

**已有基础：** v1.3.0 仓库外 spike 已覆盖部分请求链与实例隔离，范围见 `PACKAGING.md`。它没有交付本项目应用，不能将本阶段标为完成；按该证据建立可复现的项目集成测试，再补完整 TUI 与安装验收。临时验证继续放系统临时目录，失败清理；真实模型请求统一使用私有 DeepSeek 配置。

**已落地的首个切片：** 当前仓库已有完整模块目录、严格 TS/构建/测试配置，以及 `src/pi/` 无界面宿主基础层和最小 CLI 帮助/版本入口。项目测试已覆盖原生 Session 新建/恢复/reload、工具续跑、临时内容不持久化、失败阻断、压缩隔离与项目规则/信任；真实 DeepSeek 冒烟与普通测试分开。详见 `src/pi/README.md`（相对仓库根目录）。阶段 0 尚未整体完成：仍须连接完整 TUI/交互信任、验收恢复/升级指引，并完成下面的锁定安装与失败恢复，然后进入阶段 1 的正式配置/Rule 模块。

## 阶段 0 的发布侧补充验收

在不实现业务功能的前提下，增加纯发布验证：
- 从唯一开发仓库构建最小可安装的 MemWeave 应用、版本信息与安装依赖锁；
- 检查安装包不含 `AGENTS.md`、`docs/specs/`、测试、凭据或运行时状态；仅导出必要模板资源；
- 在干净环境用锁定安装流程启动应用，验证入口、工具/hook、Rule 资源定位及没有全局 Pi 时也可工作；
- 验证运行时数据仍写入 `~/.pi/memory/`，而非应用目录；已有 Pi 用户资源不被复制或覆盖；
- 验证全局 Pi 版本变化不改变应用解析的 SDK；记录确切 SDK/Session 格式/Node/npm 版本、安装清单、命令和结果。

本阶段不要求对外发布；先完成本地可重复构建、版本目录安装与失败恢复。GitHub Release 的正式锁定安装流程见 `PACKAGING.md`；不将普通 Pi Package 的安装成功当作应用安装验收。

## 阶段 1：配置与 Rule

- 实现 `config.json` schema、默认值和非法配置错误。
- 实现白名单 `{{name}}` 替换；未知变量、缺失值、未闭合占位符必须失败。
- 每次主会话请求准备时读取 Rule；Rule、Window 选择和预算使用同一份配置快照。
- 保留原生提示词发现与信任行为。
- 在覆盖值持久化位置尚未确认前，只实现接口与测试替身，不自行决定文件格式。

**验收：** 参数变更后下一次请求生效；模板错误阻断发送；reload 不重复 Rule；不同 Session 不互相污染。

## 阶段 2：Task 管理

实现 `task_create/find/resume/status`、全局索引元数据、当前 Session/branch Task 绑定。Agent 创建 Task 时生成项目名、摘要和关键词；Goal 改变时同步更新摘要/关键词。

**验收：** 一个 Session 可切换多个 Task；Task 可跨 Session 恢复；`task_find` 只发现不恢复；`task_resume` 明确切换；多 Pi 窗口不会通过共享的 `current_task` 互相切换。

## 阶段 3：Symbolic State 最小闭环

先实现 JSONL event store、schema validation、ID 生成、evidence 校验、reducer、`state.md` renderer，再注册 `state_append/update_goal/modify_fact/state_read/state_remain`。

接着实现 State 活动窗口：
- `state_remain` 只接受本批候选事件，保留数量同时受 1/10、KEEP_LIMIT、候选数量约束。
- `slide_window` 轨迹追加到 `state.json`。
- `batch_id` 幂等；持久化失败不推进活动窗口、不清除提醒。
- `state.md` 可从事件记录重建。

**验收：** 重建前后 State 一致；非法 evidence 被拒绝；同批重试不重复追加/滑动；失败后能恢复待处理批次。

## 阶段 4：Recent Window

实现完整交互事件索引、N/B 选择、统一正文截断、最新真实用户消息豁免、末尾 State 注入、两类临时提醒及 Recent Window 提交生命周期。

- 每条真实用户消息为独立事件。
- 一次 assistant 返回及其全部关联工具结果为一个完整事件。
- 提醒不进入 Session、不计入事件数。
- 为让模型检查待移出内容，提醒请求可以临时包含待移出批次。
- `state_append` 与 Window 滑动是独立提交；前者失败不伪造成功，也不重复推进后者。
- 扩大窗口必须从原始 Session 重新选取，不能拼接已截断文本。

**验收：** 工具调用/结果不拆分；边界正确；扩大窗口能恢复原文；失败重试不重复移动；原始 Session 未被改写。

## 阶段 5：`memory_read`

实现统一已知引用读取工具，支持批量 refs、字符 `offset`、单条 `limit`、总字符上限和完整性状态。底层复用 Pi SessionManager 与文件读取；不引入摘要模型。

**验收：** U/A/T/R 的映射正确；跨 Task 不会误读同编号；offset/limit 与总预算符合契约；一个无效引用不会掩盖其他成功结果；无原件时不谎称完整。

## 阶段 6：恢复、并发与端到端集成

测试重启、分支切换、多个 MemWeave/Pi 进程、配置覆盖、工具并行调用、磁盘写入失败、重复请求、状态重建和旧 Session 兼容边界。按 `ARCHITECTURE.md` 在相关模块实现前确认持久化缺口，不等到本阶段才决定格式；实例替换后继续使用同样的适配约束。

## 每个阶段的交付格式

- 修改文件与模块；
- 依据了哪些规范章节；
- 运行过的测试命令与真实结果；
- 未运行/未验证的测试；
- 新发现的规范冲突和待用户决定事项；
- 明确确认没有改动的无关文件。


## 发布准备（不改变核心实现）

核心功能通过集成测试后：
1. 从仓库源码生成可重复构建产物，不维护手工复制的第二套源码。
2. 对构建产物执行文件白名单检查，不包含开发规范、内部技术规格、测试、用户数据或秘密。
3. 验证安装、版本切换、升级失败恢复与卸载；保留用户规则、配置、凭据、Session 与 `~/.pi/memory/`。版本回切前单独检查数据兼容性。
4. 对当前应用/Pi v1.3.0 组合完成全部验收；后续按应用需求选择 Pi 升级，不随上游自动升级，每次随新的 MemWeave 版本发布对应锁和兼容结果。
5. Pi API 差异收敛在 `src/pi/` 与依赖/构建配置，具体函数可等价调整；若公开 API 缺失或必须改变核心设计、实现效果、既定协议，先报告并与用户讨论，不静默降级。
