## 阶段 0：最小原生 Package 与关键接入验证

目标是验证原生扩展足以承载既定记忆机制。使用可丢弃测试夹具，不提前实现全部业务。

### 0.1 最小工程和可加载入口

- 从当前仓库建立 TypeScript strict、开发依赖锁、单元/集成测试入口。
- 使用 Pi v1.3.0 精确开发依赖，生产 peer 按官方约定；不捆绑另一份宿主 SDK。
- 显式 `pi.extensions` 指向可直接加载的 TypeScript 入口；仅注册验证所需工具和 hook，测试工具不进入正式产品接口。
- 从唯一模板来源生成并校验必要默认 Rule 资源；Git 发布 ref 也必须具备资源，不维护手工同步副本。

### 0.2 必须先通过的技术检查

1. 一个 `context_with_system` 内先读取同一配置快照并渲染 Rule，再做预算/State 组装；首次请求和工具续跑均更新，原生 SYSTEM/APPEND/工具结构保留。
2. 模板无效、读取失败、预算超限时先 `ctx.abort()`；以模型调用计数/本机 HTTP 为证据，保留“只 throw 仍会继续”的反例，不能将返回空消息当取消。
3. 有效 `compaction.enabled=false` 时不进入阈值、overflow/length 自动压缩；手动压缩取消。保留“仅取消 hook 仍可能写 context_edit”的反例，不再要求其他 Pi 完全不受设置影响。
4. 验证全局/受信任项目设置优先级、reload、设置变更；准确说明同范围其他进程何时读取新值，以及禁用后设置仍保留。
5. reload、新建/恢复 Session 后只保留一份处理器；临时 Rule/State/提醒不持久化，不更换 agentDir，不改用户提示文件。
6. 普通模型先验收实际请求；强制提示覆盖、虚拟路由、MCP/codemode 动态声明单列测试和未验证边界，不通过时不静默改变预算。
7. 核验实际模型的精确 token 容量及公开适配入口，快照中派生半额 C；覆盖 Pi 目录与供应商元数据不一致时的诊断。DeepSeek 官方示例 1,048,576 与本机目录 1,000,000 的差异必须先核实，不能将展示值“1M”直接换算或 patch 宿主目录。

### 0.3 最小安装与真实模型冒烟

- 在系统临时目录验证本地目录和 npm 归档解包后的同一入口可直接加载；检查 Git 选定 ref 的入口/资源一致性。完整 npm/Git 远程源安装升级留在阶段 6，不为阶段 0 另建安装服务。
- npm 归档检查白名单；Git checkout 允许有开发资料，但不得加载包内 AGENTS/规范作为用户上下文。
- 以测试替身和本机 HTTP 完成主要失败路径后，使用仓库外 DeepSeek 配置做一次必要的主会话冒烟，分别报告，不能把 HTTP 替身称为真实模型验证。
- 临时产物/Session 在成功和失败后均清理；正式可复现测试代码保存在仓库。

**退出条件：** 最小包可加载，关键时序、取消与副作用有项目测试和真实观察；不 fork Pi，不新增生产业务工具或持久化协议。部分高级组合可明确列为未验证，不能用它们阻止普通模型闭环，也不能宣称它们已兼容。

本阶段的最小安装与真实模型冒烟已通过，可以进入阶段 1；不为发布便利延长为独立安装器或 TUI 项目。后续接入真实模块时持续运行阶段 0 测试，不能把请求夹具的通过结果作为完整记忆 Runtime 验收。

## 阶段 2：Task＋State 最小认知闭环

**进入前：** 确认 `ARCHITECTURE.md` 中的 U/A/T 跨 Session 映射、Task 绑定及 Session/branch 覆盖位置；引用数据不另建一份全量聊天副本。

先实现完成闭环必需的 storage 路径/原子写/追加、State schema/reducer/renderer 和已知引用定位，再接 Task 工具；这些是最小依赖，不提前扩建通用框架。

交付顺序：

1. `task_create` 创建 Task、初始化 Goal、写索引并绑定当前 Session/branch。
2. 原始消息与已完成工具的引用可校验，`state_append` 批量写入最小 Fact/Decision，下一请求末尾只出现一份当前 State。
3. `task_find/status` 按规范查询；`task_resume` 恢复 Task 及当前认知，保留恢复请求的近期过程。
4. 重启后恢复同一 Task，继续原编号；不同 Session 的当前绑定不互相覆盖。

**验收：** “创建 Task → 获取证据 → 保存认知 → 下一请求可见 → 重启恢复”通过。按规范报告部分写入失败，不伪成功；若实现需要新增事务记录或字段，先讨论。此时不开启正式 Window 裁剪。

阶段 2 已通过：正式工具与原生加载器闭环、磁盘重开/reload、跨 Session/fork 编号、tree 绑定与共享 State、证据/批量/幂等、并发与部分失败。常规测试和真实 DeepSeek 分开执行，证据见 `PHASE_2_VALIDATION.md`。未开启 Window 裁剪；完整 State 窗口仍属阶段 3。

## 阶段 3：完整 Symbolic State

2026-10-21 确认 State §15：当前 Goal 不占 F/D 窗口容量，满窗提醒期间正常载入新认知、允许临时超过 2000；保留项维持原顺序，批次定位写入 Pi custom，不新增 State 文件。

在阶段 2 的事件记录/reducer 上补齐 `update_goal`、`modify_fact`、`state_read`、`state_remain`；`state_append` 沿用已验收接口。

- `modify_fact` 原子 archive＋append，证据和 Task 作用域校验；Goal 更新同步摘要/关键词。
- `state.md` 可从 `state.json` 重建，不引入第二份事实源。
- State 窗口按 2000/100/200/20 和比例限制运行：满窗时管理最早 200 个候选，比例上限 200 与 KEEP_LIMIT=20 取更小值；`slide_window` 轨迹写入既有事件流，同 batch 幂等。
- 提醒是临时内容；写入失败不推进活动窗口或清除待处理批次。

**验收：** 工具 schema/结果符合规范；默认 2000 事件容量和 200 候选批次正确，保留数不超过 20；重建一致；非法 evidence、并发和持久化失败可诊断；同批重试不重复提交，窗口提交点可恢复。

## 阶段 4：`memory_read` 与原件定位

将原计划中位于 Window 之后的原文回读提前，避免先启用截断却没有可靠回读路径。

- 实现规范规定的批量 U/A/T/R、字符 offset/limit、总字符预算和完整性状态；沿用阶段 2 已确认的引用持久化方案。
- 读取 Pi Session 原件，按需保留必须跨会话存在的大输出/附件至既定 blobs；不复制所有消息和工具输出。
- 原生工具 ID、来源 Task 和多模态引用可追溯；一个坏引用不掩盖其他成功结果。
- 构建 Window 后续复用的原始事件定位与回读测试夹具，不提前开启正式滑窗或新增映射格式。

**验收：** 引用不串 Task；返回预算正确；缺失/不完整明确报告；从原始记录读取，而非从已截断文本拼回。

## 阶段 5：Recent Window

**进入前：** 批次元数据/覆盖值的持久化位置已经确认，原文回读可用，完整 State 已接通。

按三个可运行切片交付：

1. 完整交互事件索引、N/B 选取、扩大/缩小、Task 恢复范围；一条真实用户为一事件，一次 assistant＋全部工具结果为一事件。
2. 单个 `context_with_system` 内先取快照中的半额 C，再按已渲染 Rule/工具成本计算唯一 Q，输出预留不重复扣减；保留原生消息结构和必要协议字段，最新真实用户、State 和本次完整回读遵守既定豁免。
3. `recent_window_set`、待移出批次、两类临时提醒与幂等提交；`state_append` 与 Window 滑动独立提交，不混成一次事务。

**验收：** 默认满 200 个事件后加入新事件时，每批移出 40 个，仅计这一个新事件时为 161 个，提醒期间的其他完整事件照常计数；调用/结果不拆散，N/M 计数正确，扩大窗口恢复原文。核验容量 1,048,576→524,288、1,000,000→500,000 和奇数向下取整；固定成本或最小呈现超过半额 C，即使未超模型完整容量也主动取消，不削减 State 或突破上限。提醒不持久化；请求未完成或边界提交失败不重复移动。本扩展不改写原始消息，也不把 Pi 自身恢复记录误作自己的滑窗提交。
