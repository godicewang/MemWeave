# 上下文预算改造验收（2026-10-23）

## 一、结果与影响

已实现用户确认的 60% 总预算、State 默认 500 条/100 候选/100 字符、State 12.5%、Window 37.5%、系统工具 15%；N/B 省略自动、显式值与分支覆盖优先。动态预算与 State 位于同一末尾临时消息，Window 提醒在前；提醒和快照不写 Session。原生工具 ID/参数/签名、最新用户和有效完整回读保留；State 不静默截断或自动挑选认知。

小模型可能未到 500 条就收到 token 管理提醒。超 State token 准入的增长在 Task 锁内整体拒绝，原日志不变；已提交重试优先识别，已有超配额 State 可非增长修正或 state_remain。需要完整内容仍放不下时取消，并建议减小输入/回读或用较大模型整理。State 整理仍由同 Task 所有会话共享。

新建配置示例省略 N/B；已有显式配置不被升级覆盖。运行时 rule.md 仍由用户独立维护，升级时应备份并核对新的 resources/rule.md，不静默覆盖自定义模板。未引入来源核验缓存优化、第二份聊天历史、摘要 Agent、新工具或新的持久化格式。

## 二、技术证据

环境：Pi SDK/宿主 1.3.0、Node 24.22.0；真实模型为本机私有配置的官方 DeepSeek Flash。密钥始终在仓库外，临时 Session、归档、registry、验证脚本/缓存均在系统临时目录；测试失败也执行清理。

### 实际整数规划

单位 token；每项向下取整，余数归 Window。N 的计算使用 floor(3*C/8) 的基础规划，不因几个取整余数改变档位。
