## 交付行为

启用 MemWeave 后，用户可在空闲且无排队输入时运行无参数 `/memweave-restart`。命令选取近期完整事件，退出当前分支旧绑定、隔离旧 Window 积压，然后等待下一条真实用户输入。命令没有推理调用；自动 N/B 必要时仍会查询模型容量元数据。

种子最多 N 个事件。若尾部没有用户，选“最近真实用户＋末尾 N-1 个完整事件”，N=1 时只选该用户；不拆工具配对、不增加永久锚点。旧 Task/State、其他会话绑定、原始 Session 和历史引用归属保留。新 Task 从实际 `task_create` 的新 Goal/v1、空 F/D 开始。目标不明确时先澄清，不创建占位 Goal。

Pi custom `memweave.restart.v1` 只保存六项定位/参数，不保存聊天正文。意图或初始 Goal 部分提交后，重开修复同一候选；不重复生成 Goal。tree 回退可在原生 Session 的其他分支找到已提交创建操作，fork 的未完成候选按新 Session 独立。显式 N/B 变化仍按既有规则重选原始历史。

阶段节点由 Agent 按用户的可交付目标判断，Rule 和工具说明要求业务/记忆两层检查：先验证结果，再批量保存重要、尚未覆盖且有证据的 F/D；无重要新增不写。失败、暂停、验证受阻不能记成成功。没有 turn_end 自动保存、阶段状态机、新 State 类型或额外总结 Agent。

### 确定性边界

- 26000 条合成原生 user 记录只选受控近期范围；命令无推理，重试复用意图，旧 State 和原始消息不变。这些不是 State 事件，也不是 26000 次真实模型调用。
- 尾部无用户时补入最近用户；N=1、无用户、空 Session、完整 assistant/工具配对覆盖。
- Scope 写入失败、初始 Goal 已提交但索引/绑定未提交、磁盘重开、原调用幂等重试、SDK cwd 改变、tree 回退和 fork 独立候选覆盖。
- 5000 条合成旧认知使原请求超预算时，显式重开仍可创建新 Goal；旧文件及另一会话绑定不变。
- 首次请求前/后的有效 N/B 调整保持原历史重选；伪造种子、并发命令、非法参数和未完成输入检查覆盖。
- 普通 assistant/工具结束不产生程序自动 F/D；阶段指引实际进入有效 system 和工具声明，不持久化为聊天消息。

## 首轮问题与修正

1. 真实目标未定用例首次出现提前创建 Task。固定 Rule、工具说明及末尾程序提示明确“先判断目标是否选定，先讨论时只澄清，禁止占位 Goal”，同步两份模板后，真实重测通过。程序仍不伪造 Goal 或自动填充认知。
2. 首次完整入口有 245 项通过、1 项因 npm 下载旧宿主超过 120 秒失败；未降低断言，原入口重跑 246 项及后续阶段全部通过。另用本机精确旧宿主补验，没有改日常 Pi 或认证。
3. 早期把短问答放在含三个组件业务工具的合成夹具中，两次 Flash 错答为 12；出站最新用户原文完整，无意外 Task/State。原生 Pi、默认插件、无记忆工具三个对照均答 84。正式短问答用例改用实际默认插件工具集合，保留 84 断言并通过；额外工具组合的误答原因未定位，不能宣称已修复模型算术或任意工具组合质量。
4. 临时归档驱动首轮将内存对象与重开 JSON 比较，Pi 未落盘的 `usage: undefined` 导致不等；改为磁盘记录对磁盘记录及原字节前缀核验后通过，未修改产品消息或放宽持久化断言。

## 限制与收尾

阶段语义仍由模型判断，5 个真实用例不能保证任意任务永不漏记或误判。自定义旧 Rule 不会在同包版本下被强制替换；全套新指引随默认资源交付，现有工具包含核心提示。没有针对本次新增命令重新执行人工 TUI 操作，也未运行本次候选的完整 Git 安装/卸载矩阵；实际 SDK 命令、两宿主相关集成和解包运行已覆盖。未执行 npm 发布。

临时驱动、源码副本、日志、合成 Session/State 与归档在收尾删除；正式可重复测试保留在 tests 中。密钥、完整真实请求与用户运行数据没有写入报告或 Git。
