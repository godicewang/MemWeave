结构原子性、Rule 渲染、Window 配对/引用保真及恢复隔离继续由现有产品单元/集成测试验证。本轮报告未把这些测试冒充正式模型运行中的完整契约采样率；缺少必要检查点的扩展指标明确未覆盖。开放文本的重要性/完整语义保真、所有 C1–C8/T1–T4 真实环境组合、账户实际扣费、精确完整请求 token 分块及全系统 I/O 尚不能据本次单题宣称已证明。

Task 公式：前 K 先按原顺序去重；有效 limit<K 为未知；limit≥K 的自然短列表有效，已知空结果计未命中。Recall@K 按每查询相关覆盖比例宏平均；条件 Top1 仅以最佳集合已入围的机会为分母。恢复端到端包含所有合格继续意图，绑定后率只诊断子集。创建按持久 ID 去重并按逻辑机会计；缺创建列表不当作空列表，null 布尔值不当 false。简单任务同时要求正确完成及原投影未变。所有分母、未知及 N/A 数量单列。

两组额度各累计 12 美元，全部重试与重跑共用同一 budget_id 账本；缺 usage 保留完整预留。仅确认 token 后结算，confirmed cache-hit 可退差额。账本金额是峰值价保守费用上界，不是供应商账户账单。原第1节的 Session-only `model_request_attempts=null` 保留兼容，新传输数据位于 `engineering_metrics.http_attempts`。

用于观察 MemWeave 是否按预期运行。它们是诊断指标，不替代官方任务评分，也不证明记忆的因果收益。用户于 2026-10-29 要求加入以下两个口径；离线 `memweave-eval report` 在 schema1 和 schema2 的每个任务／变体／重复运行行中生成 `state_metrics`，同时写入 CSV 和 Markdown。历史重试仍单列，不与主运行合并。

## 共用来源与计数

- 模型调用量 `model_responses_with_usage`：本任务原始 Pi Session 中带 usage 对象的 assistant 返回数；不含工具调用、工具结果或压缩摘要。无 usage 的 assistant 另计；该值不能冒充 HTTP 请求尝试数。Session 没有可靠的请求尝试日志，因此 `model_request_attempts` 为 unknown/null，包含内部网络重试的总请求量不可反推。
- Session 按原生 session ID、entry ID 去重；工具尝试按 session／assistant entry／tool call ID 定位，结果沿原生父链配对。失败后模型发出的新调用计新尝试；同一调用的重复原件不重复计数。缺结果或缺 isError 保留未知，成功率为成功／尝试，只有全部结果已知且尝试非零才给出。
- `state_append` 的尝试、成功、失败、未知和成功率单列；`modify_fact`、`update_goal`、`state_remain`、`task_create` 各自单列。task_create 的初始 Goal 不属于 F/D。
- 累计新增事件从该 Trial 已收集的 `agent/memory.tar.gz` 内各 Task 的唯一 `state.json` 重放；按 task_id／op_id 去重。append_fact、append_decision 每条计一事件，modify_fact 计一个新 Fact；Goal、归档和滑窗操作不增加事件数。失败回执中的部分提交仍按落地日志计数，幂等重放不增加。累计新增与最终活动存量分列，归档／移窗不扣累计数。
- 报告只读取原始解题 Trial 的哈希校验证据，不读取评分重放或历史诊断重试。缺 archive、缺 Session、坏行、来源缺字段或无法精确定位时明确 unknown；unknown 不当作 0。原始 Session、State、提示和预算不被修改。

## 1. State 事件和模型调用量的比例

定义：`r = 累计新增 F/D 条目数 / 带 usage 的 assistant 返回数`。分母是调用次数，分子是条目数，不是成功批次数。

正常闭区间为 `0.05 ≤ r ≤ 0.10`，即每 10–20 次模型返回产生一个 F/D。`r < 0.05` 预警 `too_sparse`，`r > 0.10` 预警 `too_dense`；两端等于边界不预警。100 次返回、一次批量写 5 条得到 0.05（1:20）；写 10 条得到 0.10（1:10）；写 11 条得到 0.11，预警过密。

零分母不计算比例；零事件且分母非零得到 0 并预警过稀。少于 20 次返回另标 `short_sample`（实现采用的观察门槛，不是用户指定的告警阈值），仍展示比例与方向，但不能据此判定长期习惯。任一 assistant 缺 usage、State 原件缺失或损坏时比例未知。事件总量可知但无法定位其来源调用时，保留总量和比例，均匀度另标未知。

解释：过稀可能漏存关键认知，过密可能记录琐事或修正过多；应检查内容、证据及任务阶段。此区间用于实验观察，不成为 Agent 的强制写入频率，不改变 prompt。

## 2. State 写入均匀程度

按有新 F/D 实际提交的工具批次定位到来源 assistant 的模型返回序号 `p1,…,pk`；同一批多条仍只记一个位置，同一返回多次独立写入可产生零间隔。幂等重放／未提交的失败不产生位置。归档、Goal 更新、state_remain 不算新增写入。

内部间隔为 `di = p(i+1)-pi`，单位为模型返回次数。报告间隔序列、均值、总体标准差／均值（CV）和最大间隔；另外列开始到首次写入 `p1` 及末次写入到结束 `M-pk`，不把尾段伪装成完成的写入周期。另列包含首尾段的最大观察空档，避免隐藏末尾长时间未写入。

例：M=50、位置 `[10,25,40]`，内部间隔 `[15,15]`、均值 15、CV=0、最大内部间隔 15，首段 10、尾段 10。位置 `[1,2,40]` 得 `[1,38]`、均值 19.5、CV≈0.949，表示明显集中写入。批次包含多少 F/D 由事件总量另行解释。

零／一次写入无内部离散度；两次写入也只有一个间隔，均标 `insufficient_sample`，不宣称完美均匀。至少三个写入批次（两个间隔）才报告 CV；全部间隔为零时均值为零、CV 未定义。缺 usage、无法按原生来源定位全部新增事件或原件损坏时为 unknown。用户未指定均匀度告警阈值，本实现只提供描述性 CV，不引入任意“正常”阈值。

解释：CV 越小，已观察到的内部周期越接近；需结合首尾段、样本数、阶段性质与事件密度，不能把 CV=0 单独当作运行正确。
