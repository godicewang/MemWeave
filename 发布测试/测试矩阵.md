# 发布测试矩阵

“必做”是新候选发布前的要求；“按影响补测”须在报告中写明执行结果或不适用理由，不能留空或把未执行写成通过。现有业务用例继续留在 tests/，本目录集中组织与补足产物验收。

| 范围 | 验收要点 | 入口/证据 | 要求 |
|---|---|---|---|
| 基础回归 | 固定 Rule 两份正文与生成资源一致、配置校验、类型、单元和原生集成均通过 | `npm run check`、`npm run build` | 必做，完整入口包含 |
| 候选归档 | 同一候选两次打包 sha512 一致；显式资源白名单；开发文档、发布流程、测试、密钥和宿主副本不进入 npm 包 | 本目录 `产物.test.mjs`、`tests/integration/package-load.test.ts` | 必做，完整入口包含 |
| 安装代码功能 | 实际归档解包加载；独立进程创建/恢复 Task，原文回读和 State 提交；Window 参数及原始消息保留 | 本目录 `产物.test.mjs` | 必做，完整入口包含 |
| 安装/升级/卸载 | npm 临时 registry 旧/新版本、Rule 覆盖、State/Session/config/auth 保留；Git 固定 ref 安装更新、禁用、reload 与移除 | `tests/distribution/*.test.ts` | 必做，完整入口包含；Git 必须是本次候选 |
| 真实供应商 | 包内 Runtime 在真实 DeepSeek 上恢复认知、调用 memory_read/state_append，保留磁盘原件 | `tests/live/release.test.ts` | 必做，完整入口包含；报告真实调用数 |
| 完整提示与工具环境 | Pi 原生默认 System、全部默认工具、当前完整 Rule 和生产 launcher；请求前拒绝哨兵 System、缺失工具或不完整 Rule；不把提供方独立校准当作插件验收 | production-environment 集成、production-session fixture、解包 release-worker 与 live 专项 | 真实供应商/发布验收必做；不缩减候选行为或修改业务源码 |
| 宿主兼容 | 每个继续支持的 Pi 精确版本实际执行基础入口；旧产品在真实旧宿主生成数据，新宿主恢复 | 各宿主的 `test:release` 与 `release-recovery.test.ts`、分发升级 | 必做；当前完整入口只运行当前宿主，不能推断其他版本 |
| 首次初始化与升级 | 回车确认/取消、Rule 替换、全局关闭压缩、其他配置保留、reload；独立重启不重复覆盖，版本变化覆盖一次 | `tests/integration/setup.test.ts`、真实 Pi CLI PTY 记录 | 自动回归必做；首发和相关变更补真实终端 |
| 启动模式 | 原生选择/取消/重试、状态提示；未启用全局恢复压缩且没有记忆工具/请求与压缩 hook；原生请求、手动/自动压缩正常；reload/new/resume/fork 延续本次选择，独立实例隔离，无界面保持旧行为 | `tests/integration/startup-mode.test.ts`、磁盘生产入口真实 Pi CLI PTY | 自动回归必做；相关变更补支持宿主及真实终端 |
| 上次请求显示 | 原生底栏逐行/窄屏一致；API input+cacheRead+cacheWrite+output 与同帧核验容量配对；发送/工具结果不叠加预估，失败保留，切换/reload 未知；未启用及非 TUI 不接管 | `tests/integration/context-footer.test.ts`、startup-mode；真实 PTY 三档/缩窗，见 CONTEXT_DISPLAY_VALIDATION.md | 自动回归包含；UI/宿主/用量接线变化补兼容及真实终端；其他自定义 footer 组合单独验收 |
| 请求与失败阻断 | Rule/Window/State 同快照顺序，工具续跑；坏模板/配置/容量/预算先 abort 再报错且 HTTP 请求数为 0；重试不重复提交 | request-lifecycle、rule-http、provider-http、context-budget、settings 等集成用例 | 自动回归必做；相关变更补专项 |
| Session 与原文 | 原始消息不改写、临时 State/预算/提醒不持久化；tool call/result ID、arguments、reasoning/signature、多模态配对；可信来源失效明确拒绝 | memory-read、source-verification、read-lifetime、recent-window 等单元/集成；供应商专项 | 自动回归必做；受影响的供应商字段按实际支持范围补验 |
| 预算与双窗口 | 基础 60%＋额外最多 20%、必需成本后 40/40/20 分池且不重复核算、显式配置优先、State/Recent Window 独立边界、积压与失败不提前提交、10 条消息回读生命周期 | budget-policy、context-limit、combined-windows、state-window、read-lifetime 等 | 自动回归必做；模型/tokenizer/预算变更补真实 API |
| 弹性回读与正文 | 普通组 50/35/15 按需回收；读池不借 Window，旧回读可截断以允许 offset 续读；并行/重试共享额度，JSON/证据/图片真实完整性，到期回读合计 10%；固定 Rule 提醒而非临时加入 | tests/unit/elastic-budget.test.ts、tests/integration/elastic-budget.test.ts、tests/live/elastic-budget.test.ts | 前两项包含在常规入口；预算/回读变更额外执行真实专项，完整入口不会自动代跑所有 live 文件 |
| Task 初始化与混合召回 | 简单问答自主豁免、initialize声明/普通查找分离、业务门禁、有界回执/重启/篡改拒绝；本机语义与词项融合、缓存更新/主损坏、Agent选择；恢复旧 Task 独占事件、冻结分支、缺失/部分提交/重试及不复制原文 | task-binding、task-search、task-resume-window 集成/单元；真实 task-retrieval、restart 与 checkpoint 专项 | 新接线受影响时双宿主及真实完整环境必做；检索分数不作为自动恢复概率 |
| 恢复与并发 | 两个独立进程共享 Task 而分支 Window 隔离；旧数据恢复、派生视图重建、幂等、部分写入、死锁诊断不抢占 | release-recovery、task、state-window 等集成 | 自动回归必做；存储/恢复变更补中断专项 |
| 压缩与共存 | 全局与项目有效配置、手动取消、重新启用压缩的 context_edit 反例；SYSTEM/APPEND/AGENTS 不变，reload 不叠加 handler | compaction、coexistence、request-lifecycle 集成 | 自动回归必做；新组合单独验收，不能泛化 |
| 图片与模型变化 | 原生结构、R 引用、显式读取、原件 bytes/MIME/出站哈希、预算与供应商成功响应；OCR 内容/答复格式单独观察，不作为插件兼容门槛；新增提供方核验精确容量 | 受影响的 `tests/live/*.test.ts`、必要时 `npm run test:live` | 按影响补测，文字冒烟不能替代视觉验收 |
| 性能与调用成本 | 历史规模、缓存冷/热、请求准备耗时、内存、输入/输出预算与模型请求数按同一数据对比；检查是否引入重复加载或额外推理 | 受影响算法的固定样本与前后版本测量，记录环境、规模及变化 | 历史读取/缓存/tokenizer/预算算法变更时补测；不凭单次耗时设无依据阈值，不承诺固定缓存命中 |
| 用户安装文档 | Node 最低版本、受支持 Pi、准确的 npm 包名/版本/next、初始化覆盖与卸载保留提示 | README、USER_GUIDE 与临时干净目录 CLI | 必做；命令语法检查不能代替实际安装 |
| npm 发布结果 | 包可回读、渠道和 integrity 正确，实际下载/安装/恢复；处理传播延迟与 2FA | 目标 registry、真实 Pi CLI、独立恢复记录 | 发布后必做，不伪装成发布前已通过 |
| GitHub 镜像 | 仅授权的包名/registry 元数据差异，运行文件逐字节相同、关联仓库、实际可见性、下载完整性 | prepare-github-package、目标 Actions 与公开 Package 页面 | 仅 GitHub 发布；不以 access 参数推断公开 |

## 状态与判定

报告逐项使用：通过 / 失败 / 未执行 / 不适用（附理由）。自动测试的 skip 必须调查；预期反例断言通过与用例被跳过是两回事。任何必测失败或未执行阻断发布。网络、权限、模型不稳定导致失败时记录实际原因，修复后重跑相关阶段；禁止改成 skip、伪造成功或改包版本规避。

不承诺任意第三方组合、所有提供方、未测 Pi 版本或固定缓存命中率。当前支持范围见 docs/PACKAGING.md；新增支持需要对应验收证据，不能从 peerDependencies 的通配符推断。

本地分配/渲染性能样本：`memweave-dev node 发布测试/性能/elastic-budget.mjs`。固定 401 条文字、显式事件组、1,525,068 UTF-8 bytes，交替测旧统一配额与当前策略，预热后各 5 次；无 API、无真实用户数据，临时旧代码自动删除。两策略展示量不同，结果不能冒充等输出性能、完整 Pi Loop 耗时或长期任务质量。记录见 docs/ELASTIC_BUDGET_VALIDATION.md。
